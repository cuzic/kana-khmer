## 1. 目的と範囲

日本を旅行するクメール語話者(ADR-0010 の学習者像)が、日本語の音をクメール文字で読めるようにする補助表記の**生成規則と対応表**を定める。
出力は発音ではなくクメール語の正書法(系列の選択と慣習的綴り)なので、`khmer-kana` の逆変換ではなく別の表になる(ADR-0010 コンテキスト)。

| 範囲内 | 範囲外 |
|---|---|
| 基本46音(あ〜ん、を を含む) | 外来語音(ティ・ファ・ヴ・ウィ・ウェ・ウォ 等。ADR-0017 の仮表にある w の渡り音対応は未検証で本書の表に入れない) |
| 濁音・半濁音(が・ざ・だ・ば行、ぱ行。ぢ・づ を含む) | 漢字、かな綴りから発音への変換(ADR-0010 決定2) |
| 拗音(き・ぎ・し・じ・ち・に・ひ・び・ぴ・み・り の ゃ・ゅ・ょ) | アクセント線の描画と符号化(ADR-0010 決定6。§3.3) |
| 撥音「ん」、促音「っ」、長音「ー」の規則。連母音 あい の最小規則(§6.4) | UI、音声、フォント生成 |

表記は音声と併用する(ADR-0010 決定4)。本書の表記だけで正しい発音が伝わるとは主張しない。

## 2. 入力形式

ADR-0010 決定2のとおり、入力は**発音を確定した日本語**とする。

```
utterance = phrase { " " phrase }          ; 空白はアクセント句または語の区切り
phrase    = mora { mora }
mora      = kana | kana small | "ッ" | "ン" | "ー"
kana      = ア〜ン のうち ッ ン ー を除く1文字(濁音・半濁音を含む。ヴ は範囲外)
small     = "ャ" | "ュ" | "ョ"               ; 小書きの ァィゥェォ は範囲外
```

- 長音は `ー`(おう・おお・えい・ええ は データ側で オー・エー と書く)、促音は `ッ`、撥音は `ン`、助詞は発音どおり(は→ワ、へ→エ、を→オ)。
- 撥音の同化(後続音による ン の書き分け)は §6.1 のとおり**行わない**(多数派が ន 固定のため)。データは「ン」とだけ書く。
- **破擦/摩擦(じ・ず の [dʑ]/[ʑ])はデータの属性にしない**。`ジ` は `ジ` のまま(§3.5。標準語で中和していて、語・速さで揺れる)。
- アクセント(核の位置、語単位)は任意の付加情報で、本書は扱わない(§3.3)。
- 生成器はクメール文字を発音から規則でビルド時に生成する(ADR-0010 決定3)。規則で表せない語だけデータ側に override を持つ。

## 3. 表記の層

ADR-0010 決定3・6の表記の思想を、3つの層として定義する。

### 3.1 基底文字

クメール文字。子音字、下付き子音(coeng)、母音記号、末子音、◌៉ ◌៊ を含む。**詳細とライトで同じ**(ADR-0010 決定3)。
系列(a系・o系)の選択、母音記号、末子音は §4・§5・§6 の規則と対応表で決める。

**◌៉ ◌៊ の置き場所**は、2字で1子音を表す組と、子音+្យ(拗音)で違い、拗音の中でも ◌៉ と ◌៊ で違う。生成器は次の表のとおりに実装する。

| 場合 | 並び | 例 | 根拠(km-IPA 実測) |
|---|---|---|---|
| 2字で1子音の組(ហ្គ ហ្ស ហ្វ ត្ស)に ◌៊ ◌៉ を付ける | **coeng+子音の後**に置く | ហ្ស៊ូ(U+17A0 U+17D2 U+179F U+17CA U+17BC)、ហ្វ៊ូ、ត្ស៊ឹ | ហ្ស៊ូ /zuː/、ហ្វ៊ូ /fuː/。前に置くと別の読み: ហ៊្វូ /hʋuː/、ហ៊្សូ /hsou/(km-IPA は ហ + 下付き子音と読む) |
| 子音+្យ に **◌៊** を付ける(ひゅ・びゅ) | **្យ の前**に置く | ហ៊្យូ、ប៊្យូ | ហ៊្យូ /hjuː/、ប៊្យូ /pʰjuː/、ស៊្យូ /sjuː/。後ろに置くと **Module(km-IPA)がエラー**: ហ្យ៊ូ、ប្យ៊ូ、ស្យ៊ូ(Module の構文解析の制約で、Unicode 上の不正や描画の失敗を意味しない) |
| 子音+្យ に **◌៉** を付ける(みゃ・りゃ 等) | **្យ の後**に置く | ម្យ៉ា、រ្យ៉ូ | ម្យ៉ា /mjaː/、រ្យ៉ូ /rjou/。前に置くと o系の読み: ម៉្យា /mjiə/、រ៉្យា /rjiə/(ぴゃ の ប៉្យា と ប្យ៉ា は同じ /pʰjaː/) |

- 3つの行が別々の並びになる。**規則としてまとまっておらず**、Module が受け付ける並びに合わせただけである(§8 #15)。
- **Unicode の符号化順序との照合**: The Unicode Standard 16.0 の Khmer の章(2026-09-28 に Web の要約経由で確認。**要約を読んだだけで、原文の照合はしていない**)は、音節の構成を `B {R | C} {S {R}}* {{Z} V} {O} {S}` とし(B 基底、R ロバット、**C 登録子(◌៉ ◌៊)**、S 下付き子音、V 母音記号)、「C は基底の**直後**に置く」と述べる。
  この式に従えば、◌៊ ◌៉ は基底の直後で、下付き子音の**前**になる。
  - 拗音の ◌៊(ហ៊្យូ・ប៊្យូ。្យ の前)は、この Unicode の順序に合う。
  - **拗音の ◌៉(ម្យ៉ា・រ្យ៉ូ。្យ の後)と、補助子音(ហ្ស៊ូ など。coeng+子音の後)の並びは、Unicode の順序に合わない**可能性が高い(Wikipedia の補助子音の表、借用語調査の実例、Module の読みはいずれも「後」)。Unicode の順序どおりに書いた ហ៊្ស は、Module では別の読みになる(上表)ので、Module を読み戻しに使う限り、Unicode の順序では検証できない。
  - **描画**: Opus レビューの実測(uharfbuzz 最新版+Noto Sans Khmer Regular。本書の作成者は再実行していない)では、◌៉ ◌៊ を coeng の前後どちらに置いても、補助子音(ហ្ស៊ូ/ហ៊្សូ)・拗音(ហ៊្យូ/ហ្យ៊ូ、ប៊្យូ/ប្យ៊ូ、ម្យ៉ា/ម៉្យា)とも**点線円は出なかった**。Noto Sans Khmer は coeng の後の ◌៉ に専用の文脈異体を持つ。**未確認で残るのは iOS(CoreText。HarfBuzz ではない)と古い Android の WebView(古い HarfBuzz)**で、`glyph-check` の範囲(§8 #15)。
  - **再現手順**(スクリプトはリポジトリに入れない。手順だけ。フォントの入手元の URL は本書の作成者が再確認していない): (1) Noto Sans Khmer Regular(OFL)を notofonts の配布(GitHub の notofonts/khmer のリリース等)から入手する。(2) `uv run --with uharfbuzz python` で、フォントを `hb.Face`/`hb.Font` に読み、`hb.Buffer` に検査する綴りを入れ、`script` を `Khmr` にして `hb.shape` する。(3) 出力グリフ列に U+25CC(点線円。グリフ名 `uni25CC` 等)が含まれるかを見る。(4) 綴りは、補助子音 ហ្ស៊ូ / ហ៊្សូ、拗音 ហ៊្យូ / ហ្យ៊ូ、ប៊្យូ / ប្យ៊ូ、ម្យ៉ា / ម៉្យា、および ត្ស៊ឹ の両方の並びで見る。§9.5 の回帰テストに組み込む案(§9.5 の項目 6)。

### 3.2 右肩ローマ字

**右肩に書く記号は、IPA ではなく日本語ローマ字(ヘボン式)の上付き文字**とする(D8。ユーザー判断 2026-09-29。sh → `ˢʰ`)。ローマ字を読める学習者に読みやすく、`ᶴ`(U+1DB4)のような珍しい文字を避けられ、使う文字が日本語の音に必要なものに限られるため。クメール文字に無い音・区別を、書記音節の末尾に上付き文字で足す。**本書が採る記号は次の2つ(span 種別)だけ**。

| 記号(span 種別) | 意味 | 文字 | 詳細 | ライト(暫定) | 根拠 |
|---|---|---|---|---|---|
| `ˢʰ`(`cons-mod`) | sh(**しゃ・しゅ・しょ**。し には付けない) | U+02E2 ˢ + U+02B0 ʰ(2文字で1つの span) | しゃ・しゅ・しょ に付ける(D7) | 残す(暫定) | 3対立(サ/シャ・ス/シュ・ショ/チョ)の合計 2.06%/1.17%(JMdict 共通語/全体)が ADR-0006 の「残す」基準 2.1% に近い。し は D6 で付けない |
| **長音マーカー**(`long`。ADR-0002 の khmer-kana の span 種別 `long` に名前をそろえる。将来 `kana-core` で共通化するときに名前が割れないため) | 長音(ー) | **直前の母音の上付きローマ字+結合マクロン U+0304(ᵃ̄ ⁱ̄ ᵘ̄ ᵉ̄ ᵒ̄)**(D9で確定)。ADR-0003 の方式で、ja-khmer 用フォントに**5つの合成グリフ**を持つ。**フォールバック: 上付き母音の重ね書き(ᵃᵃ ⁱⁱ ᵘᵘ ᵉᵉ ᵒᵒ)**。`glyph-check` の実機描画確認が最終確認 | 全ての長音に付ける | 残す | 長短を潰すと共通語 11.0%・全体 6.7% が新たに同綴りになる(新表。旧表は ADR-0017 の 14.4%/8.5%。§3.6)。借用語では長音がほぼ書き分けられず(§7)、独自の記号になる(ADR-0010 決定3) |

**長音マーカーの決まっている部分**: 直前のモーラの母音(あ段 a、い段 i、う段 u、え段 e、お段 o。ゃゅょ は a・u・o)の**上付きローマ字**で、入力の `ー` と1対1。入力は発音を確定した日本語なので、おう・おお は ō、えい・ええ は ē(JMdict の読みでのかな綴りは、おう 4,050 : おお 148、えい 1,464 : ええ 25 で、共通語では おう が約 27 倍、えい が約 58 倍。この数は かな綴りの連続(お段+う、え段+い 等)を機械的に数えたもので、**形態素の境目をまたぐもの(例: 思う=おもう の も+う は長音でなく別の語尾)も含む**。おう・えい の比は上限に近い概算)全体は おう 62,666 : おお 2,335、えい 22,520 : ええ 204)(ヘボン式の綴りの ei ではなく発音基準。ᵒᵘ・ᵉⁱ にするには入力にかな綴りが要り、弁別的でないので採らない)。
**長音マーカーの字形(D9。ユーザー判断 2026-09-29: (a) に確定)**: 理由は「ローマ字+マクロンが一番現実的」。ADR-0010 決定3 の「結合文字を使わない」の**例外はこの判断で了承済み**(合成グリフで欠字を避ける。ADR-0003)。検討した案:

| 案 | 例(とう) | 構成 | 判断 |
|---|---|---|---|
| **(a) 上付き母音+結合マクロン** | តូᵒ̄ | ᵒ U+1D52 + U+0304 | **採用(D9)**。幅が1文字分で最小。ローマ字を読める人に ō として最も自然。結合文字なので、基底と同じフォントに合成グリフ(5つ)を持たないと Android の Chrome で欠字になる(ADR-0003)。同梱フォントで解く(下の作業) |
| (c) 上付き母音の重ね書き | តូᵒᵒ | ᵒ ᵒ(ā→ᵃᵃ、ī→ⁱⁱ、ū→ᵘᵘ、ē→ᵉᵉ、ō→ᵒᵒ) | **フォールバック**。(a) の合成グリフが実機で崩れたときに使う。結合文字も合成グリフも要らない。代償は幅(2文字分)と、英語を知る読み手が `ᵒᵒ` を /uː/、`ᵉᵉ` を /iː/ と読む恐れ(話者の確認が要る) |
| (b) 上付き母音+ U+02C9(結合しない macron) | តូᵒˉ | ᵒ + ˉ | 却下。ˉ は上付きサイズでなく離れて立ち、ō に見えない |
| (d) 旧案の `ː`(U+02D0。基底の右・基線) | តូː | ː | 取り下げ(D8)。ローマ字の利点が無い |
| バントック(◌់ U+17CB)で「短い」を示す | (短い拍に ◌់) | クメール文字側の記号 | **却下**(ユーザー判断、D9)。付けられるのは a系の ◌ា と固有母音だけで、ី ូ េ ិ ុ に付けられず(km-IPA で解析不能)、o系では母音の質が変わる。開音節のバントックは非標準で、短い拍が全拍の 86.1% で印が最も多くなる |
| `ー`(U+30FC)をそのまま使う | (តូー) | 日本語の長音記号 | **採らない**(ユーザー判断、D9)。日本語の文字で、クメール文字と幅・高さ・字形が合わず、ローマ字+マクロンのように母音を示せない(ū か ō かが分からない) |

**(a) を実装するための作業**(ADR-0003・ADR-0014・ADR-0016。未実施。§8 #9):
1. **5つの合成グリフ**(ᵃ̄ ⁱ̄ ᵘ̄ ᵉ̄ ᵒ̄)を描く(上付き母音の上にマクロンが載る。マクロンの高さ・幅を専用に設計する)。ja-khmer 用サブセットフォント(標準の h 字形の `ʰ` を含む。§8 #9b)に `ccmp` の合字(母音+U+0304 → 専用グリフ)で置き換える。`build-kana-font.py` と同じ手順(基底+結合文字を1つのフォントに同梱)。
2. 基底の上付き母音と U+0304 は**同じ DOM 要素(同じ span)**に入れる(ADR-0003)。
3. **欠字・位置ずれの恐れ**(失敗の型は点線円より、マクロンが出ない欠字と、上付き母音の上に載らない位置ずれ): 結合文字を、基底と別のフォントの上付き母音の後に置くと、Android の Chrome で欠字になる(ADR-0003 の実測は ◌̯)。同梱フォントで解けるはずだが、**未確認**。iOS・古い Android WebView(ADR-0016 の環境)での確認が要る。
4. 合成グリフが崩れる場合は (c) に切り替える(表・生成器は長音マーカーを1つの span 種別として扱うので、字形の置換だけで済む)。
5. NFKC/NFKD は U+0304 付きの上付き母音を平文に潰す(例: ᵒ+U+0304 は NFKC で ō(U+014D)になり、上付きでなくなる)。適用しない(CLAUDE.md の禁止と同じ理由)ことを、この例をテストに挙げて固定する。

**視覚負荷**(v0.8 で訂正): 長音を含む語は共通語 **37.1%**(8,051/21,680 語)、全体 **48.5%**(`ー` は共通語 9,617 個で1語あたり 0.44 個、全体 134,656 個)。`ー` を2つ以上含む語は 6.6% / 15.4%。「11%」は `ː` を潰したときの衝突率で、長音が付く語の割合ではない。長音マーカーは表記のかなり頻繁な要素になり、幅の差((a) 1文字分、(c) 2文字分)が効く。長音の母音の内訳(共通語)は お段 47%、え段 19%、う段 17%、あ段 10%、い段 7%(ō と ē で3分の2)。
**基底との重複**: 基底の母音記号は既に長母音記号(ា ី ូ េ)で、クメール語話者は基底から長さが分かる。右肩の母音字は重複するが、う段と お段が同じ ូ を使うので、「ū か ō か」を Latin で補う(母音字付きの長音にすると ず/ぞ・ごう/ぐう が長い拍で分かれ、基準の同綴りが全体で 380→368 語に減る。§3.6)。
**しょう の並び**: ឆូ+`ˢʰ`+長音マーカー(例 ឆូˢʰᵒ̄ = shō)。順序は 子音の印 → 長音マーカー に固定する。

**記号の基準(D5。ユーザー判断)**: 右肩・長音などの記号は、**日本語で弁別的な対立のうち、衝突率が ADR-0006 の基準以上のものだけ**に付ける。実現差(破擦/摩擦、語ごとの [dʑ]/[ʑ] など)は表記しない。衝突率が低いものは、詳細でも同綴りを許容する(§3.5 の案Y)。記号が増え続けるのを防ぐ歯止めである(ADR-0010 決定3に追記済み)。
**判断の単位**(D5): 基準を当てる単位は、**行や対立ではなく記号(ADR-0002 の span 種別)**である。ライトの導出は記号単位で落とすので(§3.4)、記号が担う対立を同時に潰したときの衝突率で判断する。
**基準の読み方**(D5): ADR-0006 の閾値は 2.1% 以上を残し、0.5% 以下を落とす。D5 の「基準以上」は、**2.1% 以上は必ず付け、0.5% 以下は付けず、その間(0.5〜2.1%)は個別に判断する**と読む。判断に使う語彙は**共通語を主**とし(旅行者の日常語に近いため)、全体は参考にする(ADR-0006 が両方を示すのと同じ)。
**詳細の意味が khmer-kana と違う**: ADR-0002 の「詳細」は全ての音韻対立を書く階層だが、ja-khmer の詳細は、基準以上の対立だけを右肩に書く。基準未満の対立(ず/ぞ、じゃ/ちゃ)は詳細でも書かず、同綴りを許容する。ライトは、詳細から機能負担量の低い記号を落としたもの(ADR-0006 と同じ)。
**現在の記号を基準に照らすと**、長音マーカーは 11.0%/6.7%(共通語/全体。新表で測り直した値。旧表は ADR-0017 の 14.4%/8.5%。§3.6)で付ける。**`ˢʰ` は、今の表で sh が担う対立を、同じ方法(JMdict。§3.5 の測り方)で測り直した**(ADR-0017 の 2.5%/1.4% は、ソ/ショ を含む旧表の値で、今の表の対立ではない。しょ=ឆូ は そ=សូ と基底で既に分かれる):

|---|---|---|---|---|
| サ/シャ | シャ→サ | 0.54% | 0.30% | 単独では 0.5% 前後で「付けない」側に近い |

**`ˢʰ` は しゃ・しゅ・しょ の3つ全部に付ける**(ユーザー判断 D7、§8.1。上の「判断の単位は記号」から D5 のまま導ける: `ˢʰ` は1つの記号で、担う3対立の合計が 2.06%/1.17%、共通語で 2.1% に近いので付ける)。理由: (1) 記号は1つで、ライトの導出(ADR-0002。`LITE_DROP` は span 種別単位)も3つをまとめて扱うので、判断の単位は3対立の合計(共通語 2.06%。§3.6)で、ADR-0006 の「残す」基準 2.1% に近い。(2) 単独では 0.5% 前後の対立も、3つそろえた方が sh の印として読める。**し にだけ付かない不統一は許容する**(D6): し は表に相手が無く、詳細でも対立を担わないので D5 を文字どおりに適用し、し行の統一のためには付けない。付けない案・一部だけ付ける案との比較は §8.1。数値は `tools/ja-khmer-spike` による新表での測定(§3.6)。

**し の `ˢʰ`(D6)**: し には付けない。し は詳細でも対立を担わず、し行の統一のために付ける案は、D5(記号を増やさない歯止め)に反するので採らない。しゃ・しゅ・しょ の `ˢʰ` は「sh の印」で、し には付かない(不統一は許容)。

**ローマ字にしても増える記号は無い**: ヘボン式のつづりが2文字以上になる行(ち・ちゃ の ch、つ の ts、ふ の f、じ・じゃ の j、ざ行の z)は、基底が既に一意か、同綴りの衝突率が 0.06〜0.10% で基準未満なので、D5 のとおり付けない。`ˢʰ` だけが残る。

**文字の入手性と字形**(未確認を含む):
- 上付きのラテン文字(ˢ U+02E2、ʰ U+02B0、ᵃ U+1D43、ᵉ U+1D49、ⁱ U+2071、ᵒ U+1D52、ᵘ U+1D58。ほかに ᵗ ᶜ ʲ ᶻ ᶠ)は全て**独立した spacing modifier letter(Lm)**で、**Noto Sans Regular に全て入っている**(fontTools で確認。2026-09-29)。U+0304(結合マクロン)も Noto Sans にあるが結合文字(Mn)。現行の `kana-support.woff2`(16 グリフ)には ʰ ᶜ ʲ ʳ などしか入っておらず、ˢ ⁱ ᵃ ᵉ ᵒ ᵘ などは**足す作業が要る**(ADR-0014 の方式。ja-khmer 用のサブセットフォント)。
- **`ʰ` の字形の衝突**: `kana-support.woff2` の `ʰ`(U+02B0)は ADR-0015 の**カスタム字形(点+テール)**で、「h の音を足す」と誤読されないための字形。`ˢʰ` の ʰ は本当に **h の意味**なので、ja-khmer 用には**標準の h 字形の別フォント**を用意する(D8。ADR-0014 の4つ目。同じコードポイントを同じフォントで使えない)。
- **同じページでの併用**: khmer-kana(カナ。カスタム字形の ʰ)と ja-khmer(標準の h の ʰ)を同じアプリのページに出す場合は、`font-family` をコンポーネント単位で分けて、`ʰ` の字形が混ざらないようにする(ADR-0014 の4つ目のフォント)。
- **有気との誤読(未確認)**: ខ ឆ ថ ផ は有気の子音字で、IPA を知る人は `ʰ` を有気と読む。しょ の基底 ឆូ は有気(/cʰ/)で、その右に `ˢʰ` が付くので、「有気の ឆ にさらに ʰ」と読まれる恐れがある(ˢ と ʰ を離さず一体で描く、1つの合字にする、で緩和できる)。ローマ字を知る人は sh と読む。**実際にどう読まれるかは話者の確認が要る**。
- **古い Android・iOS での欠字と、合成グリフの崩れは未確認**(実機未実施)。`glyph-check`(ADR-0016 の環境)での実機描画確認が**最終確認**で、崩れたら (c) 重ね書きにする。
- NFKC/NFKD は上付き文字を `<super>` 互換分解で平文に潰す(ˢʰ→sh、ᵒ→o)。CLAUDE.md の禁止どおり適用せず、テストで固定する(ローマ字の右肩は特に事故が起きやすい)。

規約(ADR-0010 決定3が「設計書で規約にする」とした点):

- 右肩記号(`ˢʰ`)と長音マーカーは**書記音節(基底+末子音)の末尾にしか置けない**。頭子音・母音・末子音のどれを指すかは曖昧になる。本書の2記号は、長音マーカーは直前のモーラの母音、`ˢʰ` は音節の頭子音を指すと決める。ん・っ の末子音が同じ書記音節に入るときの並びは §6.3 で未決とした。
- **長音マーカーは右肩に置く**(D8。v0.7 までの `ː`(基底の右・基線・通常サイズ)は取り下げた)。字形は (a) 結合マクロンに確定(D9。フォールバックは (c) 重ね書き)。幅・並び・行分割・nowrap は `glyph-check` で確認する(未確認)。
- 右肩のラテン文字がクメール文字の辞書による行分割を乱すので、書記音節+右肩は `white-space: nowrap` で包む(ADR-0010 決定3)。(a) の結合マクロンは、基底の上付き母音と**同じ span・同じフォント**に入れる(ADR-0003)。
- 上付き文字も NFKC/NFKD を適用しない(CLAUDE.md)。
- km-IPA は右肩記号を読めない。§9 の読み戻しは基底だけを対象にし、右肩は別の検査にする。

### 3.3 アクセント線

ADR-0010 決定6のとおり、文字の上の線で表す。**符号化・描画・ライトに残すかは本書では決めない**(別途)。本書の入力形式(§2)は、アクセント情報を付けられるようにしておくだけにとどめる。

### 3.4 詳細とライト

- 詳細 = 基底 + 右肩(`ˢʰ`。しゃ・しゅ・しょ)+ 長音マーカー(長いとき。字形は (a)。§3.2)。記号はこの2つの span 種別だけ(D5)。
- ライト = 詳細から右肩の span を機能負担量で選んで捨てたもの(ADR-0002 方式・ADR-0006)。基底は同じで、差は記号の**追加**だけ。
- **ライトの扱い(暫定)**: 長音マーカー(結合マクロン付きの上付き母音。D9)は 11.0%/6.7%(新表。旧表 14.4%/8.5%。§3.6)で残す。**`ˢʰ` も残す**(ライト=詳細)。理由: ADR-0006 は 2.1% 以上を残し、0.5% 以下を落とし、間は個別判断とする。`ˢʰ` を落とすと しゃ/さ・しゅ/す・しょ/ちょ の3対立が同時に潰れ(ADR-0002 の導出は span 種別単位で、行ごとには落とせない)、その合計は 2.06%/1.17%(共通語/全体)で、共通語では 2.1% に近い。D7 で詳細に付けると決めたものを、基準に近い値のライトで落とす理由が無いので、暫定で残す。その結果、**現時点でライトに落とす記号は無く、ライトは全行で詳細と同じ文字列**になる(ADR-0006 が挙げた負の影響が極端になった形)。
- **ライトで `ˢʰ` を落とす場合(検討した案)**: ライト = 詳細から `ˢʰ` を除いた形になり、**しゃ=さ(សា)、しゅ=す(ស៊ូ)、しょ=ちょ(ឆូ)がライトで同綴り**になる(合計 2.06%/1.17%)。落とす場合は、`ˢʰ`(`cons-mod`)を `LITE_DROP` に入れる。`LITE_DROP` は span 種別単位で、`ˢʰ`(2文字)も長音マーカー(重ね書きなら2文字、結合マクロンなら母音+U+0304)も**1つの span**として扱う。将来ライトで落とす記号が出たときも同じ扱いになる。新表で衝突率を測り直してから確定する(§8)。

### 3.5 同じ基底になる組は許容する(案Y。D5)

ユーザー判断(v0.4・v0.5): **多数派の綴りを優先し、そのために別のかなと同じ基底になる行があっても、基底は変えない**(v0.3 の規則5は廃止)。さらに**衝突率が基準を下回る組は、詳細でも同綴りを許容し、区別記号を足さない**(D5。案Y)。

**同じ綴りになる組**(全104行を、詳細・ライト × 短い拍・長い拍の**4つの形**で、母音字入りの長音マーカー(§3.2)を前提に機械的に検査した。詳細とライトは全行で同じ文字列(§3.4)なので、詳細とライトの結果は同じ。短い拍と長い拍では結果が違う(下の表)):

| 組 | 短い拍の綴り | 長い拍(長音マーカー入り) | 語彙の衝突率(JMdict 共通語 / 全体。短い拍) | 扱い |
|---|---|---|---|---|
| ず・づ と ぞ | ហ្សូ(同綴り) | **分かれる**: ずー・づー=ហ្សូ+ᵘ̄、ぞー=ហ្សូ+ᵒ̄ | 0.07% / 0.06% | 短い拍は**許容**(詳細もライトも同綴り。意図した許容) |
| じゃ と ちゃ | ចា(同綴り) | 同綴り(どちらも ចា+ᵃ̄) | 0.06% / 0.10% | **許容**(短長とも) |
| お と を | អូ | 同綴り(អូ+ᵒ̄) | (同音) | 意図した同綴り |
| じ と ぢ | ជី | 同綴り(ជី+ⁱ̄) | (同音) | 意図した同綴り |
| ず と づ | ហ្សូ | 同綴り(ហ្សូ+ᵘ̄) | (同音) | 意図した同綴り |

**長い拍で残る同綴り**は、お=を、じ=ぢ、ず=づ(意図)と、じゃ=ちゃ(許容)だけ。**ず・づ と ぞ は、短い拍では同綴りだが、長い拍では長音マーカーの母音字(ᵘ と ᵒ)で分かれる**。字形が (a) 結合マクロンでも母音字は同じなので結果は同じ。

- お=を、じ=ぢ、ず=づ は発音が同じ。入力は発音を確定した日本語(§2)なので、データ側でも書き分けない(ADR-0006・ADR-0017 の衝突率も同音の語は先に除く)。
- しゃ(សាˢʰ)と さ、しゅ(ស៊ូˢʰ)と す、しょ(ឆូˢʰ)と ちょ(ឆូ)は、`ˢʰ` で分かれる(詳細もライトも)。**ライトで `ˢʰ` を落とす案(§3.4)では、この3組がライトで同綴りになる**。ごう(ហ្កូ+長音マーカー)と ぐう(ហ្គូ+長音マーカー)はガ行 (B) で分かれ、**長音マーカーが母音字を含むので、ず/ぞ・ごう/ぐう は長い拍でも分かれる**(§3.6)。他に意図しない同綴りは無い。
- **衝突率の測り方**は ADR-0006・ADR-0017 と同じ: 1つの対立を潰したとき、新たに同綴りになる語の割合(同音の語は先に除く)。JMdict 3.6.2+20260928191014 の仮名表記を発音風カタカナにした語(共通語 22,508、全体 205,730)で、ズ→ゾ、チャ→ジャ、シャ→サ、シュ→ス、ショ→チョ(ˢʰ の3対立。§3.2)の置換により同じ形になる語を数えた。表の綴りを通しておらず、基底が同じになる組を潰す操作と同じ結果になる。測定は `tools/ja-khmer-spike`(README)。新表全体での再測定は §3.6。
- **語彙の同綴りが 0.06〜0.10% にとどまる**ので、ADR-0006 の「0.5% 以下は落とす」に照らして記号を足す機能上の利点が無い。旅行者向けの補助表記で、この差の取り違えは文脈で補える。

**破擦/摩擦は表記しない**(D5): 日本語の じ・ず・ざ行は、破擦音 [dʑ][dz] と摩擦音 [ʑ][z] の両方で発音されうる。英語版 Wikipedia "Japanese phonology"(2026-09-28 取得)によると、**Maekawa, K. (2010) "Coarticulatory reinterpretation of allophonic variation: Corpus-based analysis of /z/ in spontaneous Japanese", Journal of Phonetics 38(3), 360–374(doi:10.1016/j.wocn.2010.03.001。書誌は Wikipedia の脚注から。数値は Wikipedia 経由で、一次(原論文)は未確認)**の自発話コーパス研究として、標準語では両者の区別は**中和**しており、どの位置にも両方が現れ、破擦になる確率は ん の後で平均 60%、っ の後で 74%、休止の後で 80%、発話が速いほど摩擦が増える。ぢ・づ の綴りは音の違いを示さない。日本語教育の教材は「語頭と ん・っ の後は破擦、語中は摩擦」と条件つきの異音として説明する(検索結果の要約で確認。本文は精読していない)。**おじいさん の じ は摩擦、火事 の じ は破擦、のような語ごとの実現は、出典を確認できていない**(NHK 日本語発音アクセント辞典の本文も未確認)。入力にも、破擦/摩擦の属性は持たせない(§2)。じ行の有声性が基底で表せない事実(ជ ច は無声の /c/)は、§5.1 の △ として残す。

**検討した案**(採用は Y):

| 案 | 内容 | 判断 |
|---|---|---|
| **Y(採用)** | 詳細・ライトとも同綴りを許容する | D5 の基準に合う。記号が増えず、欠字の恐れも無い |
| X(取り下げ) | 詳細に区別記号を足し、ライトで落とす: ず・づ に `ᵚ`(ɯ。U+1D5A)、じゃ に `ᶾ`(ʒ)。じゃ の記号は、有声の破擦/摩擦が語ごとに揺れる(実現差)ことを踏まえ、`ᶽ`(ʑ)・`ᵈᶾ`・`ᶾ` の代替を比べたが、実現差は表記しない方針(D5)で取り下げた | 衝突率が 0.06〜0.10% で、基準を大きく下回る。記号が増え続ける歯止めに反する |

## 4. 母音の割り当て

### 4.1 規則

借用語調査の実例(197 行)を、モーラとクメール文字の音節に機械で対応づけて数え(§11)、次の規則を立てた。**規則は実例の多数派に従う**(ユーザー判断)。

| 規則 | 内容 |
|---|---|
| 規則1(子音字) | 行の子音字は、借用語の実例で多数派の字にする。少数派は採らない(ざ行 ហ្ស、ぱ行 ប៉、拗音 ្យ、ら行 រ など。§7)。**ガ行だけはユーザー判断で (B)**(あ・え・お段 ហ្ក、い・う段 ហ្គ。行の多数派は ហ្គ 13語 : ហ្ក 8語だが、あ・え・お段 は ហ្ក が最多) |
| 規則2(系列) | 母音に合わせて a系形・o系形を選ぶ。あ・え・お は a系形、い・う は o系形。o系の共鳴音は ◌៉ で a系にし(ម៉ យ៉ រ៉ វ៉ ប៉)、a系の ស ហ ប は ◌៊ で o系にする(ស៊ ហ៊ ប៊)。な行は ណ(a系。な・ね・の)と ន(o系。に・ぬ)。実例と一致し、机上確認の系列表とも整合する |
| 規則3(母音記号) | 段の既定は**母音全体の最多の記号**: あ ា、い ី、う ូ、え េ、お ូ(§4.2)。**短い拍だけ**でセルを見て、そのセルに3語以上と独立な出典(借用語調査の参照定義 `[rN]` が異なるもの)3以上があり、6割以上の語が同じ別の記号なら、**短い拍の基底**はセルの多数派にする(該当: こ ុ、と ុ、ほ ុ、る ុ、ご ុ、つ ឹ)。**長い拍の基底は段の既定**(こう=កូᵒ̄、とう=តូᵒ̄、ほう=ហូᵒ̄、ごう=ហ្កូᵒ̄、るー=រូᵘ̄、つう=ត្ស៊ូᵘ̄。§4.3・§6.3)。ごう と ぐう(ហ្គូ+ᵘ̄)は、ガ行の (B)(あ・え・お段 ហ្ក、い・う段 ហ្គ)で分かれる。じょ は 3語(ចុ)が同一記事の語で独立出典が1なので例外にしない |
| 規則4(実例なし・割れ) | 実例が無い、または割れているセルは、規則1〜3で作った候補を置き、状態を「要決定」または「根拠弱い」にする。推測の綴りを実例一致とは書かない |
| 規則5(同じ基底の組) | **廃止**(v0.4。ユーザー判断)。規則1〜3で多数派の綴りを採った結果、別のかなと同じ基底になる組(ず/ぞ、ちゃ/じゃ、しょ/ちょ)があっても、**基底は変えない**。しょ/ちょ は ˢʰ で分かれ、ず・づ/ぞ と じゃ/ちゃ は衝突率が低いので**同綴りを許容**する(D5、§3.5) |

**「多数派」の数え方**: 多数派は、**子音字・系列(◌៉ ◌៊ の有無)の次元ごとに**数える。**母音記号の次元だけは、次元ごとの多数派ではなく規則3の判定(短い拍・3語以上・独立出典3以上・6割以上)で決め、満たさなければ段の既定にする**(例: ぐ は ហ្គឹ・ហ្គឺ の 2語で ឹ/ឺ 系が 2/2 だが、3語未満なので既定の ូ)。**規則3が ◌ិ を選ぶセルが出ても、§6.5 が優先し、段の既定に戻す**(該当セルは現状無い。ち は ិ 6 : ី 6 で閾値未満)。1つの綴り全体が過半になる必要はない。ふ は ហ្វូ が 5/12語で最多にすぎないが、子音字 ហ្វ 10/12語、◌៊ なし 10/12語、母音記号 ូ 系 7/12語と、次元ごとには多数派なので ហ្វូ になる。ね(នេ 3・ណិ 3・ណេ 2)も、系列 ណ 5 : ន 3、母音 េ 5 : ិ 3 から ណេ になる。**過半に満たない首位は「最多」と書く**(本書の「多数派」は過半を指す)。§5.1 の状態は「採用した綴り全体が過半か」を別に見る。

実例で規則から外れる**例外(多数派をそのまま採った)**は、ふ(a系 ហ្វ + ូ)、め(o系 ម + េ)、ガ行(ユーザー判断で (B)。ហ្គ を使う ぎ・ぐ・ぎゅ は系列が資料で食い違うため要決定)。読み戻しが日本語から外れるので、対応表で ⚠ を付けた。

### 4.2 母音記号の実例集計

借用語調査を対応づけた**拍数**(語の重複を除いていない)。長音は借用語調査の モーラ 欄で `:` が付いたもの。

| 母音 | 短い拍 | 長い拍 |
|---|---|---|
| あ | ា 198、(記号なし 12) | ា 1 |
| い | ី 103、ិ 36 | ី 2 |
| う | ូ 36、ឹ 21、ុ 18、ឺ 2 | ូ 6、ឺ 5 |
| え | េ 29、ិ 14、ា 1 | េ 4 |
| お | ូ 56、ុ 50、ោ 1 | ូ 36、ុ 1 |

- あ・い・え は既定の記号(ា ី េ)が明確な多数派(94%、74%、66%)。
- **お・う は割れる**。お は短い拍で ូ 56 : ុ 50 とほぼ拮抗し、長い拍では ូ 36 : ុ 1。う は短い拍で ូ 36 : ឹ 21 : ុ 18 で、過半の記号が無い(長い拍は ូ 6 : ឺ 5)。母音全体の最多の記号を既定にしたが(お は短長合計で ូ 92 : ុ 51、う は ូ 36 が最多)、根拠は強くない。
- 長い お段が ូ にほぼ固定なので、**長い拍の基底は段の既定(ូ)にする**方針(§4.3)と矛盾しない。短い拍は、セルごとに規則3で決める。

読み戻し(km-IPA 実測。子音字 ក=a系、គ=o系。`ហ្ក`/`ហ្គ` は補助子音で、Module はそれぞれ a系・o系として読む):

| 子音字 | ា | ិ | ី | ឹ | ុ | ូ | េ | ោ |
|---|---|---|---|---|---|---|---|---|
| ក(a系) | kaː | keʔ | kəj | kə | koʔ | kou | keː | kao |
| គ(o系) | kiə | kiʔ | kiː | kɨ | kuʔ | kuː | kei | koː |
| ហ្ក | ɡaː | ɡeʔ | ɡəj | ɡə | ɡoʔ | ɡou | ɡeː | ɡao |
| ហ្គ | ɡiə | ɡiʔ | ɡiː | ɡɨ | ɡuʔ | ɡuː | ɡei | ɡoː |

| かな | 系列と記号 | か行の例 | 読み戻し |
|---|---|---|---|
| あ | a系+ា | កា | /kaː/ |
| い | o系+ី | គី | /kiː/ |

**お段の a系+ូ の読み戻しは `ou`**(の /nou/、も /mou/、よ /jou/、ろ /rou/、ど /ɗou/、ほう /hou/ など)で、日本語の単母音 [o] からはやや外れる。借用語の実例の多数派に従った結果で、対応表では個別に ⚠ を付けない。短い拍で ◌ុ を採るセル(こ・と・ほ)は /koʔ/ /toʔ/ /hoʔ/(短母音+声門閉鎖)。Wikipedia(Huffman。Battambang 周辺の方言)の表は a系の ◌ូ を単母音 [oː] とし、Module(Phnom Penh)は /ou/ とする。方言・表記法の差で、どちらが旅行者の読みに近いかは決めない(§9.3)。

### 4.3 長短をどう書くか

ADR-0010 のコンテキストが示すとおり、クメール文字は母音の長短を必ず書き分ける。日本語の短い開音節(か)を長い開音節(កា)で書くと、長音(かー)との区別が潰れる。選択肢は3つある。

- **案A(採用)**: 短い拍の基底は規則3(§4.1)で決める。**長い拍は、段の既定の長母音記号(ា ី ូ េ)+ 長音マーカー**(右肩の上付き母音+結合マクロン。字形は D9 で確定。§3.2)で書く(ユーザー判断: 長音は専用のマーカー。借用語ではほぼ書き分けられない)。
  - 例外でないセルでは、短い拍と長い拍の基底が同じになる(か=កា、かー=កា+長音マーカー)。借用語の実例が ា ី ូ を長短に関係なく使う慣習と一致する。
  - 規則3の例外セル(こ・と・ほ・る・ご・つ)だけ、短い拍が ◌ុ ◌ឹ、長い拍が段の既定(◌ូ)で、**基底が変わる**(ほ=ហុ、ほう=ហូ+長音マーカー。つ=ត្ស៊ឹ、つう=ត្ស៊ូ+長音マーカー)。長い拍の実例は お段で ូ 36 : ុ 1 とほぼ ូ に固定なので、長音がこの形になることをデータが支持する。例外セルでは、クメール語の読みでも長さが区別される(/hoʔ/ と /hou/)。
  - ◌ិ が末子音の前で母音が変わる問題(§6.5)も避けられる。
  - **代償**: 例外でないセルでは、短長どちらもクメール語の読みは長母音になり、日本語の短母音とは長さがずれる。長音マーカーの有無はクメール語の読みでは区別されない。
- **案B(不採用)**: 短い拍は短母音記号(ៈ ិ ុ)、長い拍は長母音記号(ា ី ូ)にする(ADR-0017 の仮表の方式)。長さがクメール語の読みでも区別される。**代償**: ◌ិ が末子音の前で別の母音に変わる(§6.5)。◌ៈ ◌ិ ◌ុ は終子音なしで声門閉鎖を伴う(kaʔ、kiʔ、kuʔ)。借用語の実例は短い拍でも長母音記号が多い(あ ា 198/210 拍)ので、実例の多数派と食い違う。
- **案C(検討したが採らなかった)**: 長音の第2拍を、独立の音節 អ+母音 で書く(借用語調査に せい=សេអ៊ី の実例がある。#176。せい=សេ の実例は #33)。**クメール語の読みでも2拍分の長さが伝わる、通常の文字だけでできる唯一の方法**で、案A の代償を相対化する比較としてここに書く。不採用の理由: (1) 長音は専用の長音マーカーで書くというユーザー判断。(2) 第2拍が声門閉鎖を挟む(អ៊ូ /ʔuː/)ので、日本語の長母音と別の音になる。(3) 書記音節が増えて語が長くなる。

案A で進めるが、**クメール語話者が長母音を日本語の短音として読み替えられるか**は文献では確かめられない。母語話者の確認が要る(§8)。

## 5. 対応表

### 5.1 凡例

- **詳細**は基底+右肩、**ライト**は §3.4 のとおり。表の綴りは**短い拍**の基底(長音マーカーを含まない)。**長音**は詳細・ライトとも、段の既定の長母音記号にした基底の直後に長音マーカーを足す(例 とう → តូᵒ̄。例外セルの こ・と・ほ・る・ご・つ は短い拍と基底が違う。§6.3)。
- **km-IPA 読み戻し**は、`{{km-IPA|<基底の綴り>}}` を英語版 Wiktionary の API(`action=expandtemplates&prop=wikitext`)で実行した標準クメール語の IPA(2026-09-28 実測、Module:km-pron の機械出力)。話者の実音ではない。右肩記号は読まれない。子音の ɓ ɗ(ば・だ行)、r(ら行)、ʋ(わ)、有気(ち・か の異形)などの音価差は右肩に回さない(機能負担量が無いため)ので、読み戻しの差として現れるが行ごとには印を付けない。

### 5.3 濁音・半濁音

**ガ行は (B)(ユーザー判断)**: あ・え・お段は ហ្ក、い・う段は ហ្គ(が=ហ្កា、ぎ=ហ្គី、ぐ=ហ្គូ、げ=ហ្កេ、ご=ហ្កុ)。行の多数派は ហ្គ(13語 : ហ្ក 8語)だが、が の単独では ហ្កា が最多(5/9語)で、Module の読みで あ・え・お段(/ɡaː/ /ɡeː/ /ɡoʔ/)と い・う段(/ɡiː/ /ɡuː/)がすべて日本語の音に一致する。これで ごう=ហ្កូ+長音マーカー と ぐう=ហ្គូ+長音マーカー も分かれる。

### 5.4 拗音

拗音は「子音字+្យ+母音記号」の型が実例(東京 តូក្យូ、九州 ឃ្យូ…、琉球 រ្យូ…)で一貫している。ただし、33行のうち実例があるのは 8行(きゅ・きょ・しゅ・しょ・じゅ・じょ・ちゃ・りゅ)だけで、**25行に実例が無い**(うち 10行は、きゃ・ぎゃ・しゃ・じゃ・にゃ・ひゃ・みゃ・りゃ・びゃ・ぴゃ で、かな表に候補がある)。状態は §5.1 の基準どおり、採用形がかな表にあれば根拠弱い、実例にもかな表にも無ければ要決定とした。

## 6. 撥音・促音・長音、連母音

### 6.1 撥音「ん」

**既定は末子音 ន 固定**(ユーザー判断: 多数派。後続音で ម ង に書き分けない)。

- 借用語調査を対応づけた範囲で、末子音として現れた ん は ន 28(ន់ を含む)、ង 5、ម 1。語末は ន 14/14。ង 5 のうち 3 はホンダ系(#123,124,179)で、残りは 日本語(#17)と 音読み(#40)。ម は 神武 だけ。ំ は ガンバ・ちゃん・さん で 3(集計外で確認)。
- 後続音で ម ង に同化する規則(ADR-0010 決定2が生成器に持たせるとした案)は、**多数派ではない**ので既定にしない。実行するプロファイル(方言プロファイル、ADR-0010 決定3)としては残せる。読み戻し(実測): សាម-ប៉ូ /saːm.pou/、សាន-ប៉ូ /saːn.pou/、ហុង-ដា /hoŋ.ˈɗaː/、ហុន-ដា /hon.ˈɗaː/。どちらも別の語として読める。
- ◌ំ(ニクヒット)は音節全体の母音が変わる(ា+ំ = /am/、ហ្គាំ = /ɡŏəm/)ので使わない(机上確認 §5)。
- 語頭・単独の ん と、語末の「ンッ」等の感動詞: 実例なし。**要決定**。

| ឿ ៀ ួ | **/kɨəʔ/ /kiəʔ/ /kuəʔ/(声門閉鎖)** | **同左** |

  声門閉鎖になるのは ា と二重母音 ឿ ៀ ួ だけ。本書の基底で該当するのは ា(あ段+っ+k/g)だけで、ほっかいどう=ហុក-កៃដូ(ុ)などは /k/ のまま。
- バントック(◌់)は使わない。គីត់ のように ី と組むと km-IPA が読めない(実測)。កាត់ /kat/ は母音を短くするので長母音記号の基底(§4.3 案A)と合わない。
- 語末の ッ(あっ、えっ 等): 実例なし。**要決定**。
- 促音を書かない型(借用語調査 型(c))と、同じ字を coeng で重ねる型は使わない(重ね書きが重子音として読まれる証拠が無い。ADR-0010)。

### 6.3 長音「ー」

- **全ての長音に、直前のモーラの基底の直後へ長音マーカーを足す**(ユーザー判断)。マーカーは直前の母音の上付きローマ字+結合マクロン(§3.2。**字形は (a) に確定(D9)**。フォールバックは (c) 重ね書き)。長い拍の基底は**段の既定の長母音記号**(ា ី ូ េ。§4.3 案A)。例: 東京 → តូᵒ̄ក្យូᵒ̄、ラーメン → រ៉ាᵃ̄មេន。
- **規則3の例外セル**(短い拍で ◌ុ ◌ឹ を採るもの)は、短い拍と長い拍で基底が違う。読み戻し(実測。基底だけを読む。長音マーカーは読まれない):

| セル | 短い拍 | 読み戻し | 長い拍(基底+マーカー) | 読み戻し(基底) |
|---|---|---|---|---|
| こ | កុ | /koʔ/ | កូᵒ̄ | /kou/ |
| と | តុ | /toʔ/ | តូᵒ̄ | /tou/ |
| ほ | ហុ | /hoʔ/ | ហូᵒ̄ | /hou/ |
| る | រុ | /ruʔ/ | រូᵘ̄ | /ruː/ |
| ご | ហ្កុ | /ɡoʔ/ | ហ្កូᵒ̄ | /ɡou/ |
| つ | ត្ស៊ឹ | /tsɨ/ | ត្ស៊ូᵘ̄ | /tsuː/ |

  例: とうきょう តូᵒ̄ក្យូᵒ̄、こうべ កូᵒ̄បេ、ほう ហូᵒ̄(ほん は ហុន)、こんにちは កុននីឈីវ៉ា、しょう ឆូˢʰᵒ̄。長い拍の同綴りは全セルで検査した(§3.5)。意図した同綴り(を=お・ぢ=じ・づ=ず)のほか、長い拍で基底が同じまま残るのは じゃ/ちゃ(許容)だけで、**ず・づ と ぞ は長音マーカーの母音字(ᵘ と ᵒ)で分かれる**。しゃ・しゅ・しょ は `ˢʰ` で さ・す・ちょ と分かれる。ごう と ぐう はガ行 (B) で分かれる。**じょ は例外にしないので、じょう=ចូ+マーカー(短い じょ も ចូ)**。
- 根拠: 借用語調査の長音は専用の字を持たず、ラーメン រ៉ាមេន(ា)、ソニー សូនី、すもう ស៊ូម៉ូ(ម៉ូ)のようにほぼ書き分けられない。**長い お段は ូ が 36 : 1** なので、長い拍の基底を ូ にすることをデータが支持する。したがって既存の慣習と衝突せず、長音マーカーは独自の記号になる。
- **未決**: (1) (a) の合成グリフと、実機の描画確認(§3.2 の作業。§8 #9)。(2) ん・っ の末子音が同じ書記音節に入るとき(らー+ん、こー+っ)、マーカーを末子音の前後どちらに置くか。右肩は書記音節の末尾に置くので(§3.2)、末子音の後ろに来る(§8)。

### 6.4 連母音 あい

- **あい は ៃ 1文字で書く**(あ+い を別々の音節にしない)。借用語調査のあい系 8語(9行: #10,11,15,58,82,86,102,103,107。#10 と #11 は同じ語)は全て ៃ。
- 実測: កៃ /kaj/、សៃ /saj/、ម៉ៃ /maj/、រ៉ៃ /raj/、ហៃ /haj/、ណៃ /naj/、ដៃ /ɗaj/、អៃ /ʔaj/。
- 状態: あい は**実例一致**(8語で全て ៃ、読み戻しも /aj/。§5 の104行には数えていない)。うい・おい・えい・おう は、別の音節に分けて書く実例が多い(えい は せい=សេ と សេអ៊ី が併存)ので、本書では「各モーラを別に書く」とし、専用の規則は持たない(**要決定**)。

### 6.5 ◌ិ ◌ុ が終子音の前で母音が変わる問題への対処

ADR-0010 は「◌ិ は [ə]/[ɨ] に、◌ុ は [o]/[u] に変わる」と書いた。実測では**変わるのは ◌ិ だけ**で、◌ុ と ◌ឹ は終子音なしの読み(声門閉鎖を除く)と同じ母音のまま。

| 綴り | 終子音なし | 終子音あり |
|---|---|---|
| គិ → គិន | /kiʔ/ | /kɨn/(**i が ɨ に変わる**) |
| កិ → កិន | /keʔ/ | /kən/(**e が ə に変わる**) |
| ឈិ → ឈិន | /cʰiʔ/ | /cʰɨn/(**変わる**) |
| គុ → គុន | /kuʔ/ | /kun/(変わらない) |
| កុ → កុន | /koʔ/ | /kon/(変わらない) |
| គឹ → គឹន | /kɨ/ | /kɨn/(変わらない) |

対処案(本書の採用):

1. **基底に長母音記号を使う**(§4.3 案A)。គីន /kiːn/、ឈីន /cʰiːn/ のように、ん・っ の前でも母音は変わらない(§6.1、§6.2 の実測)。
2. ◌ុ・◌ឹ を採るセル(こ・と・ほ・る・ご・つ)は、終子音の前でも母音が変わらないので問題は出ない(ហុន /hon/、រុន /run/、ត្ស៊ឹន /tsɨn/)。ただし ご は ហ្គ の系列の問題(§5.3)が別に残る。
3. **◌ិ は基底に使わない**。え段を ◌ិ で書く実例(14 拍。え・て・ね・め・れ・べ 等)は採らない。え段は េ で、ん・っ が付いても /eː/ のまま(កេន /keːn/)。

## 9. 読み戻し検証の方法

### 9.1 位置づけ: 回帰テストであり、音の妥当性の独立した検証ではない

ADR-0010 決定7(a)を具体化するが、次の限界を先に明記する。

- **Module:km-pron による読み戻しは、表を変えたときに読みがどう変わるかを見る回帰テストである。音の妥当性の独立した検証ではない。** 本書の表の値は Module の実測を見て選んでいる(状態の判定、⚠、規則5の衝突回避、ぎょ に ហ្ក を使ったこと、◌ិ を避けたこと)。その表を同じ Module で読み直しても、「同じ理解から期待値を作る」構造(ADR-0009 が問題にしたもの)は避けられない。
- 見出し語の `{{km-IPA}}` を集計する方法も、多くは引数なし(綴りから決定的に出る)なので、Module の出力を集め直すだけで新しい情報はほぼ入らない。今回の走査では、Wiktionary のクメール語の借用語見出し 619 ページのうち 391 ページが引数なしの `{{km-IPA}}` だった。
- 見出し語から得られる**独立した情報**は、(i) 編集者が綴りと違う入力を渡している語(Module の読みが話者の読みと違う証拠。§9.4)と、(ii) 英語版 Wikipedia "Khmer script" の母音表(Huffman 由来。Module とは別系統。§9.3)だけである。

### 9.2 実測の方法と、表示形との食い違い

1. **実測(本書で実施)**: 候補の綴りごとに `https://en.wiktionary.org/w/api.php?action=expandtemplates&prop=wikitext&format=json&text={{km-IPA|<綴り>}}` を呼び、出力の `/…/`(標準クメール語の IPA)を読む。約800件(子音字約50種×母音記号12種の格子、候補の綴り、末子音付き、語例)を、WebFetch ではなく同じ API を Node の `fetch` で直接叩いて実行した(件数が多いため。レート制限を避けるため、1回の POST に複数の綴りをまとめ、間隔を空けた)。結果は作業用のキャッシュ(リポジトリ外)に置いた。
2. **§5 の読み戻しは単音節(基底だけ)、§6 の語例は音節ごとにハイフンで区切って測った値**である。ハイフンで区切らないと Module が音節境界を誤る(借用語調査 §3 冒頭)。
3. **しかし利用者が見る文字列にハイフンは無い。** 生成器が出す表示形(ハイフンなし)を読み戻すと、読みが変わる語がある。56語(挨拶・地名・食べ物・旅行の頻出語)で両方を測り、音の並び(音節境界の `.` と強勢の `ˈ` を除いて比較)が違った**9語**を挙げる。

| 語 | 表示形(ハイフンなし) | 音節ごとにハイフン | 表示形の読み戻し |
|---|---|---|---|
| ありがとう | អារីហ្កាតូ | /ʔaː.riː.ɡaː.tou/ | /ʔaː.riːh.kaː.tou/ |
| とうきょう | តូក្យូ | /tou.ˈkjou/ | /touk.ˈjuː/ |
| みやげ | មីយ៉ាហ្កេ | /miː.jaː.ɡeː/ | /miː.jaːh.keː/ |
| おみやげ | អូមីយ៉ាហ្កេ | /ʔou.miː.jaː.ɡeː/ | /ʔou.miː.jaːh.keː/ |
| おねがいします | អូណេហ្កៃស៊ីម៉ាស៊ូ | /ʔou.neː.ɡaj.siː.maː.suː/ | /ʔou.neːh.kaj.siː.maː.suː/ |

   - 原因は2つ。(a) ហ្គ・ហ្ស・ហ្វ の ហ が、前の**開音節の末子音 /h/** に取られる(ありがとう、みやげ、みず、じょうず、ちゅうごく、しょうがっこう、おねがいします)。実際のクメール語の読み手が coeng を見て正しく分けるかは未確認だが、少なくとも自動検証は「利用者が見る形」を読めていない。(b) ក្យ の ក が前の音節の末子音になり、続く母音も o系 /uː/ に変わる(とうきょう /touk.ˈjuː/)。
   - 他の47語は、ハイフンの有無で読みが同じだった。**「9語」は56語の標本での数**で、語中の が行・ざ行・ふ が開音節の後に来れば起きる系統的な型である。(a)は在来語でも語中の coeng 付き子音連続の1字目を前の音節の末子音として読む型(例 សិក្សា /sək.saː/)と同じで、話者も同じように読む可能性は否定できない(Module 固有の誤りとは限らない)。(b)は、**Wiktionary の見出し តូក្យូ(東京)の発音欄が `{{km-IPA|តូ-ក្យូ}}`(編集者がハイフンを入れて補正)**であることから、区切りなしの読み /touk.ˈjuː/ は実際の読みと違うと編集者が判断している証拠になる(2026-09-28 API 取得)。上表の綴りを、**「読みが割れうる綴り」**として一覧にする。生成器の出力に対して同じ検査を回し、割れた語を自動で列挙する(§9.5)。
4. **表示形の区切り(未決。§8 #16)**。案と副作用:
   - **案1 現状(区切りなし)**: 生成器はそのまま出す。上の9語のような割れが残る。ハイフンは表示に出さない。
   - **案2 音節ごとに ZWSP(U+200B)**: クメール語では語の区切りに ZWSP を使う慣習があり、行分割とコピーで区切りが残る。**実測: Module は ZWSP 入りの入力をエラーにする**(複数音節の全語がエラー)ので、読み戻しは ZWSP を除いてから行う必要がある。検索・コピーの結果に見えない文字が混ざる。読み上げ・ADR-0010 決定6 のアクセント線の幅ヒントへの影響(区切り文字が行分割・コピー・読み上げに与える影響)を確認する必要がある。
   - **案3 拍ごとに ZWSP**: 案2 に加えて、長音・撥音・促音の入る音節も拍単位で区切る。行分割が細かくなる。副作用は案2 と同じ。
   - どれを採るかは決めない。**§9.5 のテストは、ハイフン付き・表示形(区切りなし)・ZWSP 入り(除去後)の3つを読み、食い違いを一覧にする**。

| **系列の割り当て**(どの記号が a系・o系で別の母音になるか)の食い違い | **ガ行の ហ្គ**(Wikipedia の補助子音の表は a系、Module は o系)。母音記号のセルには無い(母音記号は両資料とも a系・o系で別の母音になる) | 状態を要決定にする(§5.3) |
| **方言・表記法の差**と考えられる音価の違い(単母音か二重母音か、母音の高さ) | ី a系 [ej]/əj、ឺ a系 [əː]/əɨ、ូ a系 [oː]/ou、េ o系 [eː]/ei、ៅ [aɨ]/aw・[əɨ]/ɨw | どちらが正しいかは決めない。状態は下げない |
| **方言差が大きい、または一方が首都の読みと合わない疑い** | ៃ(Wikipedia a系 [ej]・o系 [aj]、Module a系 /aj/・o系 /ɨj/) | a系の ៃ が /aj/ である読みは基本語で広く知られている(レビューの知識。未検証)。あい=ៃ(§6.4)は下げない。旅行者の出身地(未定)で変わりうる |

- **系列の割り当ては2資料で一致する**(母音記号16のうち、ガ行の ហ្គ を除く全てで、a系・o系の区別そのものに食い違いが無い)。この照合が独立な検査として意味を持つのは、ここまでである。
- **母音の細かな音価(単母音か二重母音か)は、資料が別の方言を記述している以上、この照合では判定できない**。お段の /ou/(Wikipedia は [oː])、め・ね の /mei/(同 [eː])、あい の /aj/(同 [ej])が、どちらの方言の話者にとって外れるかは決められない(§8 #17)。§4.2 の「お段は /ou/」、§5.2 め の ⚠ は Module(Phnom Penh 基準)の読みでの評価である。
- **状態の扱い**: 「食い違う組を使うと状態を下げる」規則は置かない(v0.2 の記述は、お段・あい を下げていない実際の扱いと矛盾したので、**規則の側を削った**)。理由: 方言差・表記法の差では正誤を決められず、下げる根拠にならないから。代わりに「**系列の割り当てが食い違う組(現状 ហ្គ のみ)を使う行は要決定**」とする。ガ行は既に要決定で、矛盾は無い。

### 9.5 自動テストの案(未作成。回帰テストと独立な検査を分ける)

1. **回帰テスト(Module による読み戻し)**: 表の全行と、`phrases.yaml` の発音から生成した全語を、(ハイフン付き / 表示形 / ZWSP 除去後)の3形で読み、前回の読みからの変化を一覧にする。§9.2 の「読みが割れうる綴り」を自動で列挙する。
2. **独立な検査(Wikipedia の表との照合)**: 系列×母音記号の表(§9.3。Module とは別系統)を手で固定し、生成器が使う組み合わせ(子音字の系列×母音記号×末子音)で、Module の読みと Wikipedia の読みが一致するかを機械的に照合する。不一致の組(§9.3 の8セル)は「既知の食い違い(方言・表記法の差)」印付きで固定し、系列の割り当ての食い違い(ហ្គ)を使う行は要決定に固定する。
3. **編集者の補正の一覧(§9.4)**: 生成器が出す綴りが、補正対象の型(ហ្គា、ហ្វី、ហ្សី など)に当たるとき、状態の下限を「要決定」にする。
4. **母語話者による確認**(ADR-0010 決定7(b))が、音の妥当性の唯一の独立した検証で、これは当面無い。
5. **範囲外**: 右肩の上付きローマ字(`ˢʰ` と長音マーカー)は km-IPA が読まないので、別に「基底を除いた残りが `ˢʰ` と長音マーカー(上付き母音)だけか」を検査する。NFKC/NFKD で平文に潰れていないか(ˢʰ→sh)も検査する。
6. **描画の回帰検査**: §3.1 の再現手順(HarfBuzz+Noto Sans Khmer で点線円の有無)を、生成器が出す全綴りに回す。iOS・古い Android は実機(`glyph-check`)。

## 11. 実例の集計方法と限界

- 借用語調査の第2節の表 197行のうち、日本語の音写でない 6 行(日本・NHK・JICA・ミネベア・日経・国際協力機構)を除く 191 行を、モーラ欄とクメール文字の音節に**機械で対応づけた**(モーラ列を、子音字で始まる音節の列に順に当てる。ん・っ は末子音の音節を1つ取るか飛ばす。あい は ៃ に合流。人名の姓名順の入れ替えを試す)。175 行が対応づいた。残り 16行(長文、ក់ 付きの助詞、姓名の並びが合わない行など)は集計に入っていない。
- 対応づけには、子音字の許容表(例 か行の拍は ក ខ គ ឃ で始まる音節だけ)を使い、明らかな誤対応は落としたが、**誤対応が残る可能性がある**。数は `N/M語` の形で示し、行ごとの根拠欄に借用語調査の行番号を書いたので、原表で追える。
- `語`は借用語調査の日本語欄が異なる値の数。同じ語の異綴り(安倍晋三 4行)は1語に数えた。ただし、同一記事の語(少年・少女・魔法少女の しょ・じょ)は独立した実例ではない。規則3の「独立な出典」は、出典欄の参照定義 `[rN]` の異なる数で数えた(km-wp の別記事は別の出典、同一記事の語は1)。この判定(短い拍だけ・3語以上・独立出典3以上・6割以上)は、全セルに機械的に当てた(v0.2)。
- **km-wp(クメール語版 Wikipedia)は個々の編集者の実践**で、記事間で同じ語が違う綴りになる。Wiktionary の見出し語(9語)は質が高いが少ない。実例は話者一般の使用頻度ではない(借用語調査 §5-4)。
- 借用語調査の集計・アラインメントに使った作業用スクリプトはリポジトリに無い(§8 の #13)。
