# ADR-0017: 字幕表示は日本語→クメール文字の方向に絞り、右肩 IPA の要否を語彙の衝突率で測る

## コンテキスト
Chrome 拡張(Language Reactor 系の複数字幕表示)の延長で、字幕に読みを重ねる機能を検討した
(2026-09-28)。候補は2方向あった。

- **A**: 日本語字幕 → クメール文字(ADR-0010 の方向)。日本語字幕はアニメ・ドラマに豊富にあり、
  想定学習者(日本を旅行するクメール語話者、ADR-0010)にも合う。
- **B**: クメール語字幕 → カナ。`khmer-kana` の入力は IPA(ADR-0012)なので、クメール文字 → IPA の
  変換(G2P)が要る。クメール語は分かち書きされず(`Intl.Segmenter('km')` で分割はできる)、
  正書法は系列・母音の読みが文脈で変わる。リポジトリにクメール語のコーパス・発音辞書が無く、
  YouTube のクメール語自動字幕は質が低い。

方向A の実現性を見るため、`tools/ja-khmer-spike` に使い捨てのスパイクを作った(拡張本体は未着手)。
kuromoji.js でかな読みを得て、ADR-0010 の机上メモに基づく**仮の**対応表でクメール文字にする。
その過程で、ADR-0010 決定3(右肩 IPA を機能負担量=衝突率で選ぶ)の入力になる数値を測った。

対応表の中身(系列の選び方、な行・が行の扱い、右肩記号の字形)は本 ADR では決めない
(`docs/ja-khmer-spec.md` は未作成)。数値はすべて**仮の対応表・ネイティブ確認前**の値である。

## 決定
1. **字幕拡張の変換方向は A(日本語 → クメール文字)のみとする。B(クメール語 → カナ)はやらない。**
   G2P の元になるソースが無く、精度を測る手段も無いため。B の再開条件は「クメール語の発音辞書
   (語 → IPA)またはコーパスが入手できること」とする。
2. **かな化は kuromoji の `pronunciation`(助詞「は→ワ」・長音・「行き→イキ」を反映)を使い、
   自前の読み処理を持たない。** 入力は ADR-0010 決定2(発音を確定した日本語)と整合し、字幕のような
   自由文では形態素解析の読みを「確定した発音」とみなす。読みの誤りは字幕表示側の許容とする。
3. **右肩に回す対立の候補を、ADR-0006 と同じ方法(1つの対立を潰したとき新たに同綴りになる語の
   割合。同音の語は先に除く)で測り、次を暫定方針とする。** ADR-0006 の基準(2.1% 以上は残す、
   0.5% 以下は落とす)を当てる。

   | 潰す対立 | 共通語 | 全体 | 暫定判断 |
   |---|---|---|---|
   | 長短(ー) | 14.4% | 8.5% | 残す(右肩 `ː` が第一候補という ADR-0010 決定3を裏づける) |
   | `ʃ`(サ/シャ、ス/シュ、ソ/ショ) | 2.5% | 1.4% | 右肩で書き分け、ライトに残す |
   | 有声の破擦音(チ/ジ) | 2.0% | 1.1% | 境界。残すかは別途判断(未決) |
   | 促音(ッ) | 3.4% | 1.9% | 右肩にしない。末子音(基底の文字)で書く |
   | 右肩を全部なし | 21.9% | 12.2% | 右肩なしでは足りない |

   語彙は JMdict(jmdict-simplified 3.6.2+20260928191014)の仮名表記。共通語は `jmdict-eng-common`
   (22,508 語)、全体は `jmdict-eng`(205,730 語)。同音の語を除いたうえで、対応表の未実装による
   基準時点の同綴り(共通語 106 語・0.47%、全体 361 語・0.18%)は「新たな衝突」に数えない。
4. **測定とスパイクは `tools/ja-khmer-spike/` に置き、`apps/web`・`packages/*` には入れない。**
   測定コードは `src/collision.mjs`、読みの正規化は `src/vocab.mjs`。JMdict のデータはリポジトリに
   入れない(再取得の手順は README に書く。取り込む場合の CC BY-SA(EDRDG ライセンス)の扱いは未確認)。
5. **拡張を作る場合は YouTube 限定の MV3 拡張とし、字幕は DOM 監視(`.ytp-caption-segment` の
   `MutationObserver`)で拾って Shadow DOM のオーバーレイに描く。** 字幕トラックの横取りは、
   必要になるまでやらない。`kana-c.woff2` 等のフォントは `web_accessible_resources` 経由で読み込む。
   拡張の実装は本 ADR の範囲外(未着手)。

## 検討した代替案
- **B(クメール語 → カナ)を並行して進める**: G2P のソースが無いため却下(決定1)。Wiktionary の
  `Module:km-pron` の移植で近づけるが、精度を測る正解データが無い。
- **かな化を自前で作る**: 漢字の読みは辞書が要り、kuromoji で足りるため却下。辞書の同梱サイズ
  (数十 MB)は拡張化の際に再検討する。
- **衝突率を頻度で重み付けして測る**: 頻度データが無い(ADR-0006 と同じ限界)ため、共通語と全体の
  2つの見出し語集合で範囲を示すに留めた。
- **アクセントの衝突も同時に測る**: JMdict にアクセント情報が無く、ADR-0010 決定2 の
  Wiktionary `{{ja-pron|acc=N}}` の取り込み(CC BY-SA の判断込み)が先に要るため、今回は測っていない。

## 結果(影響)
- ADR-0010 決定3の「ライトで何を残すか」に、暫定の数値が付いた。ただし対応表が仮で、系列の選び方が
  変われば数値も変わる(例: チ/ジの衝突は「母音に合わせて子音字の系列を選ぶ」規則の副作用でもある)。
  対応表を固めたら測り直す。測定スクリプトはリポジトリ内にあるので再実行できる(ADR-0006 の
  「再現手段が無い」という負の影響はここでは避けられている)。
- 測定で見つかった対応表の穴(未解決): な行・ね(ន は o系のみで ◌៉ が付けられない)、が行・ざ行
  (ហ្គ・ហ្ស の系列が資料で食い違う)、◌ិ ◌ុ の直後に末子音を付けると母音が変わる(撥音・促音)、
  「う」を ុ にするか ឹ にするか(聞き比べが必要)、語末の「ンッ」等の感動詞。ウィ・ウェ・ウォ は
  w の渡り音(វិ・វ៉េ・វោ)として対応済み。
- 右肩の記号の字形は未検証。`ᶴ`(U+1DB4)・`ᶾ`(U+1DBE)はスパイクの仮置きで、古い Android での
  欠字の恐れがある(ADR-0016、ADR-0010 が挙げた `ɾ` の懸念と同種)。`glyph-check` の目視確認が要る。
- 方向B を諦めたため、`khmer-kana`(IPA → カナ)は字幕拡張とは無関係のまま、アプリ側(`apps/web`)の
  ための資産として残る。
- 読み戻しによる機械検証(ADR-0010 決定7(a))と、`docs/ja-khmer-spec.md` の作成は次の作業として残る。
