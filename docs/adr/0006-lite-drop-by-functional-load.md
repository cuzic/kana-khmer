# ADR-0006: ライトで残す修飾文字を機能負担量の実測で個別選定する

## コンテキスト
当初のライト表記規則は「`cons-mod`/`vowel-mod` は種別で一律に落とす」だった。しかしこれだと
有気音(`ʰ`)や r/l の区別まで失われ、学習上重要な音韻対立が消えることが分かった。

## 決定
Wiktionary のクメール語見出し語(約7,700件、既存の同音異義語は除く)で、各音韻対立を1つずつ潰したときに
新たに同綴りとなる単語の割合(衝突率)を実測し、その順位で `LITE_DROP`(落とす4記号: `ˀ ᵋ ᵓ ᶤ`)を決めた。
衝突率 2.1% 以上(有気/無気 3.5%、`ɑ` 3.3%、`ə` 2.7%、語末 `ŋ`/`n` 2.2%、r/l 2.1%)は残し、0.5% 以下
(`ɨ`、`ɔ`、`ɛ`)と `ʔ`(この位置ではほぼ無音のため未計測)は落とす。

## 検討した代替案
- **種別一律で落とす(旧方式)**: 有気/無気などの学習上重要な対立まで失われるため却下。
- **会話頻度で重み付けした functional load(Jenkins の lingua franca core 方式)**: 実際の誤解事例の
  データが無く、見出し語ベースの近似値(頻度・文脈による曖昧性解消は考慮しない)に留めた。この限界は
  ドキュメントに明記している。

## 結果(影響)
新しい修飾記号を追加するたびに、Wiktionary 等で機能負担量を測って `LITE_DROP` に入れるかを個別判断する
運用になった。ネイティブ確認前の暫定値であることを明記しており、実際の誤解事例が得られ次第見直す。

**負の影響**: 残す記号が増えた分、ライトと詳細がほぼ同じ文字列になる語が増えた(例: `kʰɑːŋ` はライトも
詳細も `コʰᵅーンᵑ` で同一。`khmer-kana-spec.md` §7 の表)。`docs/design.md` §8 補足にある
「ライト→詳細への移行が学習内容になる」という設計意図は、この変更でやや弱まっている。

**再現性**: Wiktionary の衝突率を測ったスクリプト・データはこのリポジトリに無く、数値を再現する手段が
現状ない(`symbols.ts` のコメントに言及があるのみ)。
