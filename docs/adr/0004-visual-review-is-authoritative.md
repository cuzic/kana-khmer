# ADR-0004: グリフ検証は目視を正とし、自動判定は補助に留める

## コンテキスト
glyph-check CI の自動判定(canvas 比較による pixel diff)は、誤検知・見逃しが多いことが実験で分かった。
声調グリフの「別名 `U+0301` == `˦˥`」チェックでも、iOS でのみアンチエイリアシングの差による false
positive が発生し、目視で拡大比較して実際には同じ字形であることを確認した事例がある(2026-09-27。
具体的な誤検知率はセッション内の記録によるもので、本リポジトリ内では再現・確認できない)。

## 決定
各プラットフォームの実機相当環境(iOS シミュレータ、Android API 29/34)でのスクリーンショットの
**目視確認を最終的な合否判定** とする。自動判定(uharfbuzz での輪郭比較、pixel diff)は
「見るべき箇所を絞り込む補助」であり、それ単体では合格・不合格を決めない。新規/未検証の記号は
一覧の表示順の先頭に置き、端末の1画面に収まらないスクリーンショットでも見切れないようにする
(2026-09-27 の実機確認で、新規記号が写真に写らない不具合が実際に見つかり、表示順を変更して解決した)。

## 検討した代替案
- **pixel diff のみで自動合否判定する**: 上記の false positive/negative が実際に発生したため却下。

## 結果(影響)
新しい記号を glyph-check に追加するたびに、実機相当環境のスクリーンショットを人が見て確認する運用が
固定化した。自動検証(`verify-kana-multi.py` 等)は「明らかな回帰を早期に落とす」ための **手動実行の
ゲート**であり、CI には組み込まれていない([ADR-0009](0009-independent-geometry-verification.md))。
CI に組み込むかどうかは未決の課題として残る。目視確認自体も、シミュレータ・エミュレータでの確認に
留まり、実機・メーカー違いの端末での確認は `docs/design.md` §0 のとおり未了(残るリスク)。
