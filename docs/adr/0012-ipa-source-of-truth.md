# ADR-0012: 発音は IPA(音素表記)を正とし、カナはビルド時に生成する。カナ→IPA の逆変換は保証しない

## コンテキスト
`phrases.yaml` に発音情報を持たせる際、カナ表記を直接手で書くか、IPA を正として書きカナをビルドで
生成するかを選ぶ必要があった。カナを直接書くと、表記規則(ライト規則、`ʰ` の位置例外、声調位置など)を
変えるたびに全フレーズのカナを手で直す必要が生じる。また、`゚`(半濁点との兼用)や小書き `ィ`
(二重母音後半・語末 j・語末 c/ɲ の「イ寄り」に共用)のように、カナ側の記号は複数の IPA 音を指しうる
「1記号多義」の箇所があり、カナから IPA へ機械的に戻せる保証がない。

## 決定
`Syllable`(音節構造)を唯一の正とする。`phrases.yaml` には IPA を書き、`packages/khmer-kana` が
`parseIpa` で音節構造に解析し、`renderFull`/`renderLite` でカナ(詳細/ライト)を生成する
(`packages/content` のビルドで `phrases.json` に焼き込む。手で編集しない)。
`toIpa`(`Syllable → IPA`)の往復は保証するが、`カナ → IPA` の逆変換は保証しない、と原則を弱めて明記する
(「1記号1意味」原則の緩和)。

## 検討した代替案
- **カナを正として手書きする**: 表記規則の変更のたびに全フレーズを手で直す必要があり、規則変更の
  コストが高くなりすぎるため却下。

## 結果(影響)
表記規則を変えても、`phrases.yaml` の IPA は変えずにビルドし直せば全フレーズに反映される(実際に
ライト規則([ADR-0006](0006-lite-drop-by-functional-load.md))・ŋ の記号([ADR-0005](0005-ng-shared-modifier.md))
の変更がこの形で波及した)。一方で、カナから IPA へ戻すツール(逆引き・検索)は作れない、または
曖昧性を許容する形でしか作れない。衝突する組み合わせ(`ʔi`/`ji`、`ɲi`/`ni` が同じカナになる等)は
表示に支障がないため、逆変換不可を明記するだけに留める。
