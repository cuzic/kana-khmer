# ADR-0029: 韓国語字幕→カナ変換の G2P は端末内(ブラウザ拡張)で動かす前提で設計し、PoC は Python、Rust/WASM 移植は後にする

## コンテキスト
Netflix の韓国語字幕を、独自のカナ表記([ADR-0024](0024-ko-kana-notation.md) の ko-kana)に変換するエンジンを作る計画がある。
ko-kana の入力は「発音どおりのハングル」なので、**ハングル→発音ハングル(G2P)の精度が、そのまま最終表記の精度になる**。
[ADR-0017](0017-ja-khmer-subtitle-direction-and-right-shoulder-measurement.md) は「日本語字幕→クメール文字」の方向を扱っており、
本 ADR はそれとは別の計画(韓国語字幕→日本語カナ)で、0017 を改定しない。

`~/ko-pron-dict`(この repo の外)で、g2pk・mecab-ko・Wiktionary 由来の辞書を調べ、文脈依存の発音を測る最小対テスト集を
Codex と Claude の相互レビューで作って測った(2026-09-30)。

- g2pk(0.9.4)は 2022-03 から更新がなく、PR も放置されている。後続の g2pkk・g2pk2・g2pk3 も小規模で更新が止まっている。
- 最小対 188 item(現象 A〜K)での厳密な正解率は g2pk 79.3%、g2pkk 79.3%(g2pk と同一)、g2pk2/g2pk3 80.3%。
- 失敗の最大原因は品詞ではなく、**g2pk が分かち書きを越えて連音・流音化すること**(`책을 읽고→채그 릴꼬`)。g2pk2/g2pk3 は
  これを止めて I・B 群を改善したが、標準発音法 제15항の「実質形態素の前の連音」(`옷 안→오단`)まで止めて G 群が 25/26→14/26 に悪化した。
- mecab-ko の**品詞誤り**が発音を変える例が実際にある(`감기 전에`・`안기 전에`・`함께 신자` を名詞と解析して濃音化を落とす)。
  A 群(19/26)・C 群 ㄴ挿入(5/10)・K 数詞(20/26)は、どの fork でも改善しなかった。
- 数詞は g2pk が助数詞ごとの固有語/漢数詞を選べない(`3명→삼명`、`6월→유궐`)。

## 決定
1. **目標は「丁寧な標準発音」**(標準発音法)。自然な連続発話は目標にしない。分かち書きを越える連音は、제15항が定めるもの
   (ㅏㅓㅗㅜㅟ で始まる実質形態素の前)に限る。
2. **実行はブラウザ拡張の端末内で完結させる**(字幕の文を外部サービスに送らない)。字幕データは保存・再配布しない。
   Netflix の字幕は、テスト集・学習データに使わない。利用規約上の扱いは、公開前に確認する(本 ADR 時点では未確認)。
3. **PoC は Python で作る。** g2pk2 を土台にしたラッパーで、次を足す。
   - 제15항の単語間連音の再導入
   - 助数詞の表(数詞の選択)
   - Wiktionary 由来の語彙辞書による上書き(語彙的な濃音化・ㄴ挿入)
   - 個別の規則の取りこぼしの補正(`밟아`・`겉옷` など)
   - 規則エンジンの入力は**「境界の種類(語内・単語間・句間)つきの形態素列」**にする。
4. **Jev(外部 API)は実行時には使わない。** 字幕を第三者に送ることになり、端末内という前提と矛盾する。API キーも拡張に置けない。
   使うとしても**オフラインの教師**(字幕以外の韓国語の文で mecab が曖昧な箇所にラベルを付け、端末内で動く小さな判定器や規則に
   蒸留する)に限る。Jev の韓国語での有効性は**未検証**(API キー未取得、公式資料に対応言語の記載なし)。
5. **Rust/WASM への移植は PoC の後に行う。** 最初の検証は、Rust の形態素解析(lindera / vibrato + ko-dic)が mecab-ko と同じ品詞を
   返すか(最小対 198 文で比較)と、辞書のサイズ。最小対テスト集を移植の合否の基準にする。

## 検討した代替案
- **g2pk2/g2pk3 をそのまま採用**: I・B は改善するが、G が 25→14 に悪化し、A・C・K は直らない。
- **実行時に Jev で品詞を判定する**: 字幕を外部に送るため却下。
- **サーバーで変換する**: 字幕の文をサーバーに送ることになり、著作物の扱い上、端末内より不利。
- **最初から Rust で作り直す**: 失敗の大半は言語ではなく規則・設計・データの問題。規則が固まる前に移植先を二重に直すことになる。
- **g2pk に PR を出す**: 放置されており取り込まれる見込みが薄い。規則の修正は、最小の再現例つきで切り出しておき、後から出せる形にしておく。

## 結果(影響)
- 最小対テスト集(`~/ko-pron-dict/minpairs/`)を、実装の仕様として育てる。ネイティブ確認がまだで、`confidence: low` を含む。
- PoC は現在 repo の外(`~/ko-pron-dict`)にある。安定したら `packages/` 配下に取り込む(その際は別 ADR で扱う)。
- 字幕の取得方式(表示された DOM を読むか、通信から字幕ファイルを取るか)は未決。DOM 方式は文脈が現在の cue と直前の数行に限られる。
- 口語の字幕特有の入力(縮約・語尾・`ㅋㅋ`・`[음악]`・固有名詞・英語・数字)は、テスト集にまだ含まれていない。
