# ADR-0035: 母音が付く l・r は、口の形のカナを括弧で囲んだ「口形」を、ラ行の左肩に小さく書く

## コンテキスト
[ADR-0031](0031-en-kana-with-shoulder-ipa.md) は、l・r をラ行 + 右肩の `ˡ` `ʳ` で書いていた。右肩の字は小さく、ローマ字を知らない人には記号にしか見えない。

**ユーザーの発言(原文)**:
- 「ラリルレロ で、右肩に l と r を書くようにしているけど、そうではなくて、 ナニヌネノとか ウ を手前につけた上で ナニヌネノ とか ウ という口や舌の形にするんだけど、発音しないということを表現するために 例えば斜めの二重線とかで消して示すとかっていうアイデアはどうかな？？」
- 「長くなってしまうのは許容するしかないね。一回、実験的にやってみて、artifact で見せてみて」
- 「子音だけの r とか l の音は表現しようがないから、元の案のままかなぁ。母音がつく r とか l についてだけだね。あと、複合子音の場合は、手前の音が ウ段の音（ ブライトの ブみたいな）になっているはずだから、ウをわざわざ書かなくていい。」
- 「淡く小さくかつ二重斜線とかがいいかなぁ。」
- 「フォントを独自に生成して、同梱するしかないね。」
- 「淡く小さく二重斜線というのは ass 形式の字幕で表現できるのかな？ 専用のグリフを ass に埋め込むことはやってもいいです」
- 「PUA と、合字の両方に対応して、環境変数もしくはオプションで選択できるようにして。」
- (二重斜線の代案を比べたあと)「太い単線は良さそうだけど、 ニ のときに視認性悪いな、と思ったのです」「かっこ も含めて 1つのグリフにして、横幅が同じになるように調整するとか」「少し字を細くして、同じ幅にできないかな？」「少し重なってるのは調整必要だけど、これでいこう」
- (質問への回答)口形が小さく淡いと 1080p では斜線が見えず「小書き = 子音だけ」の約束ともぶつかる、への回答: 「ラの左肩に小さく書くようにして」。弱い母音(ə)が付く l・r は「右肩のままにする」。

## 決定
1. **母音が付く l は、ラ行のカナの左肩に、同じ母音のナ行(ナニヌネノ)を小さく書き、括弧で囲む**(ラˡ → ラ の左肩に `(ナ)`)。舌先を歯茎に当てる形。右肩の字(`ʳ` `ʰ` など)の左右反転で、字は小さく上寄せ。
2. **母音が付く r は、ラ行のカナの左肩に ウ を小さく書き、括弧で囲む**(レʳ → レ の左肩に `(ウ)`)。唇を丸める形。**ただし直前が ウ段のカナ(ウクスツヌフムユルグズヅブプヴ・小書きの ュ ゥ)、または子音だけの小書きカナ(ㇷ゚ ㇰ ㇱ ㇲ ㇳ ㇷ ㇺ ㇽ)なら、ウ は書かない**(ㇷ゙ラʳイ → ㇷ゙ライ)。l のナ行は直前の音では代わりにならないので、省かない。
3. **母音が付かない l・r は、右肩の `ˡ` `ʳ` のまま**(語末の `ㇽˡ`、母音の r 色の `ʳ`)。**弱い母音(ə)が付く l・r(`ㇽˡᵊ` `ㇽʳᵊ`。rural の 2 つ目の r、pilot の l)も、右肩のまま**(ユーザーが選択。弱い母音は音がほとんど出ないので、子音だけとみなす)。
4. **口形は、括弧つきの 1 つのグリフ(`(ナ)` など)で、フォント(`kana-multi.woff2`)の専用グリフにする。** 字は、細い字重(wght 300)から作り、横に縮めて(0.78 倍)小さくし、括弧はラテン文字のフォントから取る。**7 字(ナ・ニ・ヌ・ネ・ノ・ㇴ・ウ)の送り幅は同じ**で、いちばん幅のある字でも両側の括弧と重ならないように、幅を字の大きさから計算する(`build-kana-multi-font.py` の `MOUTH_*`)。字は括弧の間の中央に置く。符号化は 2 通りで、同じ字形になる。選び方は、環境変数 `EN_KANA_MOUTH` か、変換コマンドの `--mouth`(`off` | `pua` | `lig`。既定 `off`)。
   - `pua`: 私用領域の 1 字(U+E100 ナ・E101 ニ・E102 ヌ・E103 ネ・E104 ノ・E105 ㇴ・E106 ウ)。字幕レンダラーで確実。文字列として持ち出すと、フォントがなければ豆腐になる。
   - `lig`: カナ + U+0338(COMBINING LONG SOLIDUS OVERLAY)。フォントが 1 グリフに合字する。フォントがなければ、斜線(/)つきのカナに縮退する(括弧にはならない)。
5. **口形は右肩の字ではない。** ライト(右肩を除く)でも残る。
6. **ASS では、口形のグリフを淡く出す**(`\1a` `\3a` `\4a` で本文・縁・影の透明度をそろえて下げ、戻すときは Style の値に)。字形そのものが左肩の小さな字なので、`\fs` では小さくしない。フォントは `[Fonts]` に埋め込む(`--embed-font`、既定 on)。埋め込みは、小書きの濁音(ADR-0033)にも要る。kana の行だけ `\fnKanaMulti` にする。

## 検討した代替案
- **右肩の `ˡ` `ʳ` のまま**: 小さく読み落としやすく、記号にしか見えない。
- **斜めの二重斜線で消す(最初の案)**: 実寸(右肩の字と同じ約 20px)では、線同士が潰れる。ニ(横棒 2 本)では斜線が `Z` や `≠` に、ノ では字自身の線と重なって、字として読めない。
- **太い単線の斜線**: 二重線の潰れは避けられるが、ニ・ノ の問題は残る。
- **斜線の周りに白い隙間を切り抜く**: ノ は向きが同じで効きにくく、ブーリアン演算が要る。
- **上線(マクロン)**: 長音(ー)と紛れ、「消す」の意味が弱い。
- **括弧を別の文字にする(`(` + 字 + `)` を 3 字で書く)**: 幅が字によってずれ、字と括弧が重なりうる。1 つのグリフにして幅を固定した。
- **斜線を CSS・ASS のタグだけで描く**: 取り消し線(`\s1`)は水平の 1 本だけ。ベクター描画(`\p1`)は文字との位置合わせが難しい。
- **PUA だけにする**: 文字列として持ち出すと、フォントがなければ消える。持ち出す用途のために合字も残した。
- **子音だけの l・r も口形で書く**: 口の形だけで音がないので、書けない(ユーザーの指摘)。

## 結果(影響)
- 口形を、ラ行のカナの前に全角で差し込むのをやめて、左肩の小さな字にした(ユーザーの選択)。「小書き = 子音だけ」の約束とのぶつかりは、字が小書きの位置(下寄せ)ではなく右肩の字と同じ上寄せになったので、なくなる。括弧つきの一体グリフは、斜線より幅が広い(約 0.6em)。1080p での読みやすさは、実寸の目視で確かめる。
- **「少し重なっている」点**: 比較ページ(CSS の近似)で、括弧と字が少し重なって見えた。フォントでは、字の幅から括弧の位置を計算して、必ず隙間を取る。実際のグリフでの重なりは、目視で確かめる。
- **未確認**: 合字(`lig`)モードで、フォントがないときに「斜線つきのカナに縮退して意味が残る」(縮退した形は、括弧つきの左肩の字ではなく、全角のカナ + 斜線がラ行の前に並ぶ)かは、実機の標準フォントで見ていない。一般のフォントの U+0338 はラテン文字の幅に合わせてあり、全角のカナに重ねるとずれた短い斜線になることが多い。`ウ̸` は w の `ウ` と見分けにくい。
- **未決**: `en-prosody`(TS)・ブラウザ拡張にはまだ入れていない。変換は Python の `tools/en-prosody-spike/src/mouth.py` と ASS 出力だけ。TS にも入れるなら、`kana.ts` との突き合わせテストを足す。
- **古い IR のカナは、新しい規則にならない。** 入力があれば `build` で作り直し、無ければ `tools/en-prosody-spike/src/refresh_ir.py` で移行する(ADR-0033 より前の形だけ移行できる)。
- **字幕レンダラーの対応**: libass(ffmpeg・mpv・JASSUB)では、埋め込みフォントが読まれ、小書きの濁音と口形が描画されることを ffmpeg で確かめた。古い VSFilter 系は未確認。
- 口形の濃さは `to_ass.py` の `PROFILE["mouth_alpha"]`。字形の大きさ・幅・太さはフォント(`build-kana-multi-font.py` の `MOUTH_SCALE` `MOUTH_COND` `MOUTH_WGHT`)で決まり、かなの行(0.62 倍)の右肩の字と同じ程度に小さい。見やすさは、目視で調整する。
- ASS に埋め込むフォントは、`kana-multi.woff2` から字幕に要る字だけを切り出した TTF(ファミリー名 `KanaMulti`)。切り出しに 1 分ほどかかるので、一時ディレクトリにキャッシュする。
