# ADR-0007: 声調の符号化は Chao 声調文字(U+02E5–E9)を音節末尾に並べる

## コンテキスト
タイ語など声調のある言語をカナ表記に乗せる必要がある。**見た目**はカナの上に描く折れ線(矢印1本では
音域差(高/上昇 vs 低/下降)が出ないため。多言語展開の合意「声調はカナ上に折れ線」)だが、本 ADR が
扱うのは、その折れ線を**データとしてどう符号化するか**という別の決定である(折れ線の伸縮方式は
[ADR-0008](0008-tone-line-syllable-width-stretch.md))。

候補として、まず CSS ruby(カナの上に `<ruby>` で声調記号を重ねる)を検討したが、任意の折れ線を
描くには不足すると判断し、生成フォントへの移行を選んだ(多言語展開の方針の合意どおり)。
既存データには U+0300–030C の結合文字(5声調ぶんの一覧的な符号)が使われていたが、これは1音1文字の
決め打ちの符号で、任意の2点・3点の調型(山型・谷型)を表せない。U+20D0 ブロック(結合文字)も
検討したが、記号ごとに結合クラス(ccc)が 230/220/1/0 とばらばらで、NFC で並びが入れ替わってしまい、
GSUB の合成規則が拾えなくなる問題があった。

## 決定
声調は IPA の声調文字(Modifier Letter Tone Bars、U+02E5–E9)を1〜3個、音節の末尾(修飾文字の後)に
並べて表す。これらは ccc=0・カテゴリ Sk で、NFC/NFD で並びが変わらない。既存の U+0300–030C の5文字
(中/低/下降/高/上昇)はショートカット別名として残し、グリフは共有するが、新規データはすべて
声調文字で書く。

並び順は、当初(2026-09-26 時点)の合意「カナ → 声調 → `ʰ`」から、実装時に「カナ → 修飾文字 → 声調」
(声調は必ず音節の末尾)に変更した。声調が `ʰ` 等の子音修飾に割り込むと、どちらの記号がどの音に
掛かるか読み取りにくくなるため。

## 検討した代替案
- **CSS ruby でカナの上に声調記号を重ねる**: 任意の折れ線(2点・3点の調型)を描く自由度が無く、
  フォント側で解決する案に切り替えた。
- **U+20D0 ブロックの記号(矢印・ハープーン等)**: ccc の違いによる NFC 並び替えで GSUB の合成規則が
  拾えなくなるため却下。
- **既存の U+0300–030C だけを拡張する**: 任意の2点・3点の組み合わせを表せず、山型・谷型などの調型を
  汎用的に表現できないため不採用。

## 結果(影響)
声調を持つ言語パッケージ(タイ語など)は、子音の類・声調記号・母音長から声調文字列を決定するテーブル
だけを持てばよく、描画側(フォント)の変更は不要になる。クメール語のような声調を持たない言語は
`tone` フィールドを出さないままでよく、既存 golden テストに影響しない。フォント側の実装
([ADR-0008](0008-tone-line-syllable-width-stretch.md))はこの符号化を前提にしている。
