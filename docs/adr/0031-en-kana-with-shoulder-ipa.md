# ADR-0031: 英語の実際の音は、日本語話者が読める基本のカナ + 右肩の IPA 小文字で表記する

## コンテキスト
英語字幕に「実際の音」を重ねる際([ADR-0030](0030-en-subtitle-prosody-ir-and-selectable-layers.md))、カナだけでは日本語にない区別が消える(L/R、th、`æ` と `ʌ` など)。
IPA だけでは日本語話者の初学者に読めない。このリポジトリは、khmer-kana・ko-kana で「基本のカナ + 右肩の修飾文字(IPA の小文字)」を使っている([ADR-0005](0005-ng-shared-modifier.md))。

**ユーザーの発言**: 「カタカナ化は、修飾文字を使うことで、L/R や細かい母音の区別も分かるようにします」「修飾文字というのは右肩に IPA の発音記号を書くというものですね」。
個々の表記は、ユーザーが画面を見て 1 語ずつ指示した(what I → ワライ、v は ヴァ(慣用)、スィθ は シθ(幅を減らしたい)、it's の ts は ツ、future は フューチャ、in education は ネデュケイシン(のち シᵊン)、
never は ネヴァ、strange は ストレインヂ(ジ でなく ヂ))。dz は ヅ、弱い ə は今のまま、語頭の子音連続の小書きは今のまま、はユーザーが質問への回答として選んだ。

**Unicode の右肩形(`unicodedata` の名前で確認。2026-09-30 に Opus のレビューで訂正)**:
- `ʳ ˡ ʰ ᶿ ᶞ ᶺ ᶦ ᶷ ᵓ ᵊ ᵑ ᵈ ᵇ ᵍ ᶻ ᶾ ᵛ ᵗ` は、それぞれ対応する IPA の字の右肩形(`ᶺ`=ʌ、`ᶦ`=ɪ、`ᶷ`=ʊ、`ᵓ`=ɔ、`ᵊ`=ə)。
- **`ᵆ`(U+1D46)は「MODIFIER LETTER SMALL TURNED AE」で、æ ではない。** æ の右肩形は U+10783(Latin Extended-F、Unicode 14)にあるが、対応するフォントが少ない(同梱の Noto Sans の latin-ext も U+1D00–1DBF まで)。
  このため現状は `ᵆ` を**代用**している(学習者には「逆さの æ」が æ の印になる)。
- ɾ(弾き音)の右肩形は U+107A9、ɜ は `ᶟ`(U+1D9F)、r 音色は `˞`(U+02DE、RHOTIC HOOK)がある。ただし前者も U+107xx で、対応するフォントが少ない。

## 決定
**基本のカナは日本語話者が読める最も近い音にし、日本語にない区別を IPA の小文字で右肩に添える。** 実装は `tools/en-prosody-spike/src/kana.py`(挙動の正)と
`packages/en-prosody/src/kana.ts`(TS 版)。表記の文字列に NFKC/NFKD を適用しない(修飾文字が通常の文字に置き換わる)。

| 音 | 表記 | 例 | 由来 |
|---|---|---|---|
| r / l | ラ行 + `ʳ` / `ˡ` | right = ラʳイㇳ、light = ラˡイㇳ | agent |
| θ / ð | サ行・ザ行 + `ᶿ` / `ᶞ`(i の前は シᶿ / ジᶞ) | think = シᶿᶦンᵑㇰ、this = ジᶞᶦㇲ | i の前は user |
| v | ヴ行(慣用) | very = ヴェリʳー | user |
| æ / ʌ / ɪ / ʊ / ɔ | ア + `ᵆ`(æ の代用、上記) / ア + `ᶺ` / イ + `ᶦ` / ウ + `ᶷ` / オ + `ᵓ` | cat = カᵆㇳ、cup = カᶺㇷ゚ | agent |
| ə(弱い母音) | 子音の小書きカナ + `ᵊ` | about = ァᵊバウㇳ | user が現状維持を選択 |
| ɚ(弱い r 色の母音) | 子音の ア 段 + `ʳ` | never = ネヴァʳ、dinner = ディᶦナʳ | never=ネヴァ は user。ᵊʳ でなく ʳ だけにしたのは agent(幅を減らすという方針からの推論。ユーザーに確認していない) |
| 弾き音 | ラ行 + 元の音の字(`ᵗ` `ᵈ`) | what I = ワᶺ ラᵗイ | ラ行にするのは user、`ᵗ` `ᵈ` は agent |
| ts / dz | ツ / ヅ(語末でも母音の前でも) | it's = イᶦツ、kids = キᶦヅ | user |
| dʒ / ʒ / tʃ | ヂ行 / ジ + `ᶾ` / チ行(語末は チ) | strange = ㇲㇳレʳインヂ | dʒ=ヂ は user、他は agent |
| 子音 + y + 母音 | 子音の i 段 + 小書き ャュョ | future = フューチャʳ、music = ミューズィᶦㇰ | フュー は user、他は agent |
| ʃ・tʃ・dʒ・ʒ + 弱い母音 | 語末は シャ・チャ・ヂャ・ジャᶾ、音節を成す n の前は シᵊン・チᵊン・ヂᵊン、語末でない dʒ は デュ | nation = ネイシᵊン、education = エデュケイシᵊン | チャ・シᵊン・デュ は user の例から一般化(agent) |
| 母音の前以外の子音 | 母音を足さない小書きカナ(ㇰ ㇳ ㇷ゚ ㇲ ㇱ ㇺ ㇽ)+ 有声の右肩(`ᵈ` `ᵍ` `ᵇ` `ᶻ`) | strange の `ㇲㇳ` | 小書きのままは user が選択 |
| ŋ | ン + `ᵑ` | think の `ンᵑ` | agent([ADR-0005](0005-ng-shared-modifier.md) に揃えた) |

- 「詳細」は右肩の IPA を含め、「ライト」は右肩を除く(現状の実装は、`MODS` に入っている右肩の字を文字列から一律に消す)。**これは [ADR-0002](0002-two-level-notation-via-spans.md)(span 単位の 1 操作で導出し、文字列から消す方式を却下)
  とも、[ADR-0006](0006-lite-drop-by-functional-load.md)(機能負担量を測って、落とす記号を個別に選ぶ。一律に落とす方式を却下)とも違う。** 両方から外れた暫定の実装である(結果の「未決」を参照)。
- 各記法の右肩の字は、その記法の中で意味を持つ。ko-kana の `ᵓ`(ㅓ ≈ [ʌ])と本記法の `ᵓ`(ɔ)は字が同じで意味が違い、ko-kana の `ᵓ` が表す音は本記法では `ᶺ` で書く(入れ替わって見える)。
  [ADR-0005](0005-ng-shared-modifier.md) が「多言語共通」を理由に `ᵑ` を選んだ方向とは逆になる。

## 検討した代替案
- **カナだけ**: L/R・th・母音の区別が消える(ko-kana の設計でも、記号を落とした素のルビは衝突が多かった)。
- **IPA だけ**: 日本語話者の初学者には読めない。
- **IPA にない独自の修飾記号を作る**: 読み取れる根拠がなく、フォントにも無い。IPA の字そのものを右肩に置く方式にした。
- **`ts` `dz` を小書きカナ 2 字(`ㇳㇲ` `ㇳᵈㇲᶻ`)で書く**: 読めない。破擦音は 1 字のツ・ヅで書く。
- **`dʒ` をジ行で書く**: ʒ(ジ行 + `ᶾ`)と書き分けられない。ヂ行にした(ユーザー指定)。
- **弱い `ə` も全角のカナ(ハプン・セカンド)にする**: 読みやすいが幅が広がる。小書き + `ᵊ` のままにした(ユーザーが選択)。
- **子音が並ぶ語頭の小書きカナ(`ㇲㇳ`)を全角(ストレ)にする**: 幅を減らすため小書きのままにした(ユーザーが選択)。
- **æ・ɾ・ɜ・r 音色に本来の右肩形を使う**: 対応するフォントが少ない(上記)。æ は代用(`ᵆ`)にしているが、本物(U+10783)にするか、フォントを同梱するかは**未決**。

## 結果(影響)
- **対象は、デスクトップの Chrome(Windows・macOS・Linux・ChromeOS)。** MV3 の拡張が動くのはここで、Android の Chrome は拡張を動かせない。iOS/Android(`tools/glyph-check` の CI)の確認は、将来 PWA で出す場合のもの。
  `tools/glyph-check/public/en-prosody.html` と CI の配線(`.github/workflows/glyph-check.yml`)は作ったが、CI は未実行(GitHub Actions の利用枠を使うため、push の判断をユーザーに仰いでいる)。
  **デスクトップの Chrome(Windows・macOS)で `en-prosody.html` を目視確認することは、未実施の未決事項。**
  拡張の font-family は `"Noto Sans JP", "Hiragino Sans", "Yu Gothic", system-ui, "Noto Sans", "DejaVu Sans"` で、Noto Sans JP は 19 の修飾文字をすべて欠く(fontTools の cmap で確認)ので、右肩の字は 1 字ずつ別のフォントに落ちる。
  Windows・macOS で、どの字形に落ち、ベースラインと大きさがカナとどうずれるかは確かめていない。拡張はフォントを同梱していない。フォントを同梱するなら、Shadow DOM の中の `@font-face` は効かない(確度は中)ので、document 側で登録する必要がある。
  手元の Linux の Chrome では、欠字・位置崩れは見えなかった。
- **強い r 色の母音(ɝ)が、広い ɑ+r と同じ表記になる(詳細でも)。** bird = bard = `バʳㇳᵈ`、hurt = heart = `ハʳㇳ`、burn = barn、firm = farm。`VOW["ER"]` が ア段 + `ʳ` で、母音の直後の r も `ʳ` に吸収するため。
  日本語にない区別を右肩で示す、という本 ADR の趣旨に反する。**ɝ の書き分け(`ᶟʳ`・`ᵊʳ`・`ᶟ˞` など)は未決**(ユーザーの判断は弱い ɚ についてのもの。強い ɝ まで `ʳ` だけにしてよいとは言われていない)。
- **ライトが、却下された方式の繰り返しになっている。** 実際のライトの出力: the → `ㇲ`、to → `ㇳ`、a → `ァ`、that(弱形)→ `ㇲㇳ`、rice/lice = `ライㇲ`、road/load = `ロウㇳ`、thin/shin = `シン`、cup/cop = `カㇷ゚`。
  `layers.py` の入門プリセットと、拡張の既定(標準)は右肩(`ipa`)を含まないので、**初学者の既定の表示がこのライト**になり、弱形が小書きカナ 1 字になる。
  ライトで何を残すかを、ADR-0006 の方式(機能負担量を測って選ぶ。少なくとも `ʳ` `ˡ` `ᶿ` `ᶞ` は残す候補)で決めるか、弱形の `ᵊ` を残すか全角にするかは**未決**。`MODS`(右肩の字の一覧)が `ir.py`・`analyze.ts`・`overlay.ts` に重複しているので、1 か所にまとめる。
- **半母音 + ə の出力が不自然。** you(弱形)→ `イᵊ`、was → `ウᵊㇲᶻ`、would → `ウᵊㇳᵈ`(Y・W の小書き形が全角の イ・ウ のため)。一方 you're → `ヤʳ`。同じ /j/ の書き方が揃っていない。`ヤᵊ`・`ワᵊ` など、ユーザーに確認する(未決)。
- 右肩の文字が 2 つ重なる語(`シᶿᶦンᵑㇰ`)は、実機で読めるか未確認。
- 規則を直すたびに別の語の表記が変わり得る。TS 版と Python 版の突き合わせテスト(60 文)が守るのは両者の一致で、**表記が正しいことではない**(golden を作り直せばテストは通る)。
  ユーザーが語ごとに指示した表記は、期待値を手で書いたテスト(`packages/en-prosody/test/decided.test.ts`)で守る。表記の正しさの最終判断は、ユーザーが個々の語を画面で見て行う。
- 本記法は CMUdict(ARPABET、米国英語)を正とし、右肩の字はそこから写した表示用のもの(ɒ など、ARPABET にない音は書けない)。発音を IPA で持つ [ADR-0012](0012-ipa-source-of-truth.md) とは入力形式が違う。
