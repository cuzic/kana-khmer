# ADR-0032: 音声の音素認識を先生役にして、語ごとの実際の形(弱形・弾き音・口蓋化)を決める。サーバー側の任意の拡張とし、PoC の拡張には含めない

## コンテキスト
[ADR-0030](0030-en-subtitle-prosody-ir-and-selectable-layers.md) の規則による推定は、CMUdict(米国英語の引用形)と「機能語はまとまりの末尾でなければ弱形」などの規則による。
実際の発話は話者で違うので、TED の 1 本(YouTube の動画 ID `iG9CE55wbtY`、約 20 分)で、音声から認識した音素と規則を突き合わせた(2026-09-30)。
**この測定は再現できない**: 音声・認識結果(PHONES.json)・出力(`out/`、`.gitignore` 済み)・TED の字幕は、リポジトリに無い。以下の数値は、当時の実行結果を書き写したもの。

- **音素認識**: `facebook/wav2vec2-lv-60-espeak-cv-ft`(Apache-2.0。読み上げ音声 CommonVoice の書き起こしを espeak で音素にしたものを正解ラベルにして微調整した多言語モデル)の貪欲デコード。
  重みは約 1.26GB(取得したキャッシュ全体は、別形式が重複して約 2.4GB)。CPU(8 スレッド、AVX2 なし)で 1203 秒の音声を 989 秒(実時間の 0.82 倍)。
- **語への割り当て**: 自動字幕の語時刻(粗く、0.2 秒ほどずれる)の窓ではなく、認識した音素列と字幕の語ごとの期待音素(CMUdict の引用形)の、帯つき動的計画法による整列。整列の一致は全体で 80%。
  語の期待音素のうち一致・近い音に整列した割合が 0.6 未満の語は、観測を信頼しない(`observe.py` の `MATCH_MIN`)。
- **規則と音声の一致**(`tools/en-prosody-spike/src/phonecheck.py`。整列に使った語は 3,080。発音を引けて、注記でない語):
  - 弱形: 規則が弱形とした語のうち、母音が弱まったと認識されたのは 51%(419/814。欠測 67)。語によって大きく違う: `the` 144/150、`a` 65/68、`if` 23/25、`to` 64/74 に対し、
    `and` 18/92、`of` 6/56、`you` 5/50、`was` 0/32、`he` 0/17、`had` 0/12(弱まった数/測れた数)。母数が小さい語もあり、1 本の講演なので、語の性質としては読めない。
    規則が強形とした語(句末など)でも 11/43(26%)は弱まった。`it` `if` `him` のように引用形の母音がすでに ɪ の語は、ɪ を弱い母音に数えているため「弱まった」を区別できず、その語の数値は過大。
  - 弾き音: 規則が弾き音と予測した 175 件のうち、認識も弾き音は 77 件(44%)、t/d は 88 件(50%)、別の音 1 件、欠測 9 件。
  - 語末の T/D(次が子音・休止): 491 件のうち 94 件(19%)が認識されない(認識された 369、別の音 28)。
  - 口蓋化(`because you` など): 20 件のうち 7 件で語末が `dʒ` `tʃ` になった(欠測 3)。
- **IR への反映**(`observe.py`・`analyze.py`): IR の語 3,106(注記を除く。発音を引けない 26 語を含む)のうち、観測があるのは 3,080 語、信頼できるのはそのうち 89%、規則と違う形になったのは 399 語(12.8%。`of` `you` `was` `have` `that` `at` `had` が大半)。
  1〜2 音素の機能語は、1 音素違うだけで一致率が 0.5 になり、弱形の語ほど「信頼できない」として規則に戻されやすい。この偏りは、上の「89%」「12.8%」の読み方に影響する。
- **Jev**(TypeSafe AI の型つき判定モデル)でも精度を上げる検討をした。公式資料の索引には微調整の記載がなく、第三者の記事は「微調整できない。全アカウントが同じ重み」と述べている。
  入力はテキストのみで、音声は聞けない。料金は入力 100 万トークンあたり約 $0.042(第三者の記事による)。API キーは取得可能とのこと(未取得)。

**この測定が示すもの(限定)**: 「この認識器の出力と、規則の予測の一致」である。**話者の音を測ったとは言えない。** このモデルは espeak が書き起こしに付けた音素をラベルにして学習しており、出力は音響の事実より
「espeak がその語に付ける音素」に寄るおそれがある。語ごとの結果(`the` ðə・`a` ɐ・`to` tə は弱形、`was` wɒz・`he` hiː・`had` hæd・`and` ænd・`of` ɒv は強形)は、espeak-ng の英語の既定(英国英語)が機能語に付ける音素と
よく一致するように見える(未検証)。「話者は英国英語と思われる」という見立ても、espeak の既定が英国英語であることで説明できてしまう。確かめるには、同じ字幕を espeak-ng で音素にしたものと認識結果の一致率を測り、
規則との一致率と比べる必要がある(未実施)。

## 決定
1. **音声による形は、規則による形とは別の層として持つ。** IR の `kana` が音声による形(観測が無い語・信頼できない語は規則)、`kana_rule` が規則だけの形。層 `audio` で切り替える([ADR-0030](0030-en-subtitle-prosody-ir-and-selectable-layers.md))。
   ただし、上記の espeak の癖の確認が済むまでは、これを「実際の音」「話者の音」とは呼ばず、「この認識器による観測」と呼ぶ。
2. **音素認識は、弱形・強形、弾き音・t、口蓋化(音声で融合が認識された箇所だけ)の決定にだけ使う。** 認識結果をそのまま表示はしない。語末の子音の脱落・同化などの規則は、規則が観測と合うと確かめてから足す(未実装)。
3. **サーバー側の任意の拡張とする。PoC の Chrome 拡張には含めない**(ユーザー判断)。音声の取得と処理はサーバーで行う前提で、拡張は結果の IR を使う形が考えられる(未設計。IR の型も未整備。ADR-0030)。
   これは ADR-0030 の「字幕を外部に送らない」の**例外**になる。サーバーが音声を丸ごと取得して処理すると、字幕の文字列より規約・著作権のリスクが大きく、拡張がサーバーに動画 ID を送るなら視聴履歴が外部に出る。
   いずれも未確認・未設計で、公開サービスにするなら確認が要る。
4. **Jev は、音を決める用途には使わない**(音声が聞けず、微調整もできない)。使うなら、文脈が要る判定(新情報か対比か、区切りの有無)で、**オフラインの教師(ラベル付けや、しきい値の調整)に限る**。
   視聴中の字幕を Jev に送る実行時の使い方は、[ADR-0029](0029-ko-subtitle-g2p-on-device-poc-python.md) と ADR-0030 の原則に反するので採らない。「候補から選ぶ」形の質問にし、数値の比較は苦手とされるので先にコードで区分に直して渡す。
   **効果は未検証。**

## 検討した代替案
- **認識結果をそのまま表示する**: 認識には誤りがあり(整列の一致 80%)、誤った音を「正しい音」として学習者に見せるおそれがある。
- **自動字幕の語時刻の窓で音素を語に割り当てる**: 時刻が粗く、`what` の音が `I` に入るなどの誤りが出た。
- **強制整列で候補を採点する**(弱形と強形の音素列を候補にして、CTC の尤度を比べる): 自由な貪欲デコードと動的計画法による整列よりも、弱形か強形かの二択の判定に向き、espeak の癖も比べる対象にできる。**未着手で、有力な代案。**
- **Jev を微調整して音の判断を蒸留する**: できない(上記)。蒸留するなら自前の小さな分類器(語・品詞・語の長さ・無音などの特徴量)で、先生の出力を正解にする形が考えられる(未着手)。
  ただし先生の出力が espeak の癖を写したものなら、その癖を蒸留するだけになるので、espeak の癖の確認が先。
- **Whisper で音素・語時刻を取る**: ユーザーは「Whisper を使うと費用面で難しい。学習用に少数だけならいい」と言った。API か自前の GPU かは区別されていない(自前でも費用の問題になり得る)。
- **ブラウザ側で音声を処理する**: 重みが約 1.26GB あり、YouTube の音声を拡張から取れるかも未調査。

## 結果(影響)
- 音声を使う形には、サーバーと音声の取得が要る。開発サーバーの IP から YouTube に入れなかったため、Tailscale 経由の自宅の PC で yt-dlp 用のプロキシを動かして取得した(環境依存の手順で、リポジトリには含めない)。
- `tools/en-prosody-spike/src/phone_rec.py` が音素認識のスクリプト。依存(torch・transformers、モデル)は別の仮想環境に入れる。
- 評価の正解データ(「この話者が実際に言った音」)が手元に無い。話者が変わったときの結果は未測定。音声つきの確認ページ(規則と音声のどちらが聞こえに近いかをユーザーが判定する)は未作成。
- 試した範囲は TED 1 本(1 話者)。米国英語の話者、会話、速い発話では別の結果になり得る。
