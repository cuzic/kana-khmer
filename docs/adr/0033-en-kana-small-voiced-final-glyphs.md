# ADR-0033: 英語の語末の有声子音は、小書きカナ + 濁点を、小書きの ド ブ グ ズ ジ ヴ に合字して書く

## コンテキスト
[ADR-0031](0031-en-kana-with-shoulder-ipa.md) の実装は、母音の前以外の v(`love`・`of` の強形など)を `ㇷᵛ`(小書きの ㇷ + 右肩の `ᵛ`)で出していた。
ところがライトは右肩の字を一律に消す暫定なので、`love` が `ラㇷ`(= `ラフ`)になり、`luff` と区別できなかった。右肩の `ᵛ` も小さく、詳細でも `ラフ` に見えた。
語末の v は有声音で、`love`(/lʌv/)と `luff`(/lʌf/)は別の語になる。有声の語末子音は声が弱まりやすいが、母音の長さと摩擦の強さで区別される。

**ユーザーの発言(原文)**:
- 「love とかは本来 ラヴ と書くべきだと思うのですが、どうして ラフ になっているのか。」
- 「では、ラヴ であるべきですね。小文字の ヴ　とかのグリフを作成することで対応しましょう。」
- 「ㇷ゚ᵇ、ㇳᵈ、ㇰᵍ、ㇲᶻ これら、全部のグリフを作成して、対応してくださいね。」

## 決定
1. **母音の前以外の有声子音は、小書きカナ + U+3099(結合用の濁点)で書く**(g・ʒ・z・d・b は対応する無声の小書きカナ、v は小書きの ゥ)。 同梱フォント(`kana-multi.woff2`)が、この並びを 1 つの小書きグリフに合字する(ㇷ + U+309A が ㇷ゚ になるのと同じ作り。`tools/glyph-check/scripts/build-kana-multi-font.py`)。

   | 音 | 文字列 | グリフ |
   |---|---|---|
   | g | ㇰ + U+3099 | 小書き グ |
   | ʒ(語末・子音連続) | ㇱ + U+3099 | 小書き ジ |
   | z | ㇲ + U+3099 | 小書き ズ |
   | d | ㇳ + U+3099 | 小書き ド |
   | b | ㇷ + U+3099 | 小書き ブ(小書き ㇷ に濁点) |
   | v | ゥ(U+30A5)+ U+3099 | 小書き ヴ(小書き ゥ に濁点。本物の ヴ が ウ + ゛ なので、ブ と見分けがつく) |

   **フォントがなくても、どちらも意図した音に読める。** ㇷ + 濁点は ブ、ゥ + 濁点は ヴ に見える。v を ㇷ + 濁点にすると、フォントのない環境(いまの Chrome 拡張)で `love` が「ラブ」に見えて、ユーザーが直したかった「ラフ」の取り違えの逆になる(オーパスのレビューで見つかった。最初は v を ㇷ + 濁点にしていた)。ゥ + 濁点は、全角の ウ + 濁点のように NFC/NFKC で ヴ(U+30F4)に合成されることもない。
2. **右肩の `ᵈ` `ᵍ` `ᵇ` `ᶻ` `ᵛ` を、この用途では使わない。** `packages/en-prosody/src/kana.ts`・`tools/en-prosody-spike/src/kana.py` の語末(子音だけ)の出力を上の文字列にする。母音の前の `ᶾ`(ジ行 + `ᶾ`)と、弾き音の `ᵗ` `ᵈ`(ラ行 + `ᵗ` `ᵈ`)は変えない。
3. **ライトでも残る(ユーザーが確認した。2026-10-13)。** U+3099 は右肩の修飾文字の集合(`MODS`)に入っていないので、`lite()` で消えない(`love` のライトは `ラˡᶺゥ゙`)。ライトで何を落とすかの全体は `docs/en-kana-spec.md` §5 の未決 1(ADR-0006 の方式で測る)のままで、有声の印だけは残すと決まった。
4. **`ㇱᶾ`(ʒ の語末)も同じ方式にする。** ユーザーの列挙には無かったが、同じ仕組みで、ジの小書きがないと ʃ と ʒ が区別できなくなるため(agent の判断)。

## 検討した代替案
- **有声の印を右肩の `ᵈ` `ᵍ` `ᵇ` `ᶻ` `ᵛ` のままにする**: 小さくて読み落としやすく、ライトで一律に消えると `love`/`luff`、`bed`/`bet` が同じになる。
- **全角の `ヴ`**: ウ段の母音(ゥ)が付いて読まれ、幅も広がる。母音の前以外の子音を小書きで書く原則(ADR-0031 §2)に反する。
- **v を ㇷ + 濁点、b を ㇷ゚ + 濁点にする(最初の案)**: フォントがないと v が「ブ」、b が半濁点と濁点の重なりで読めない。却下した。
- **専用の私用領域(PUA)の 1 コードポイントにする**: フォントがない環境で文字が消える。2 字の合字なら、フォントがなくても読める。
- **合字せず ㇷ + U+3099 のまま**: 合字のないフォントでは、小書きのカナに濁点が浮いて見える。意味は ブ/ヴ(上の決定 1)として残る。

## 結果(影響)
- 同梱フォントの再生成と、`en-prosody.html` での描画確認(目視)が必要。**目視は未実施。** 小書きの濁点(゛)は、全角のセルの右上に置いてあり、小さい本体から離れて見える(オーパスのレビュー L1)。位置の調整は未着手。
- `packages/en-prosody/test/golden.json` の v・b・d・g・z の語が変わる。Python 版と TS 版の一致は `parity.test.ts` が守る。`decided.test.ts` に love = ラヴ(ユーザーの指示)と b/v の書き分けのテストを足した。フォントの合字は `tools/glyph-check/scripts/verify-kana-voiced.py` が確かめる。
- ブラウザ拡張はフォントをまだ同梱していない(ADR-0031 の結果を参照)。同梱するまでは、小書きのカナに濁点が付いた形で出る(上の決定 1 のとおり、意味は保たれる)。
- U+3099 を使うことの注意: NFC/NFKC では変わらない(右肩の字のように NFKC で `ʰ` → `h` にならない)。ただし、結合用の濁点を ゛(U+309B)にそろえる文字列処理や、「ド」で検索しても `ㇳ゙` に当たらない点には注意が要る。
- ASS に埋め込むときは、同じフォントが要る(ADR-0035)。
