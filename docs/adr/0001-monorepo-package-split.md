# ADR-0001: モノレポ構成とパッケージ分割

## コンテキスト
プロジェクト立ち上げ時点(2026-09-26)で、性質の異なる4つの成果物が要ることが分かっていた:
発音のカナ変換だけを担う表記ライブラリ(他言語展開時に切り出す可能性がある)、フレーズデータの検証・ビルド、
PWA 本体、そして実機依存でジョブの種類も違う描画検証ツール。これらを1つのパッケージにまとめると、
表記ライブラリのテスト(Vitest)とアプリのビルドが密結合し、将来の多言語展開(`packages/kana-th` 等)で
表記ライブラリだけを切り出しにくくなる。

## 決定
pnpm workspace のモノレポとし、次の4パッケージに分割する。

```
packages/khmer-kana/   表記ライブラリ(Vitest)
packages/content/      phrases.yaml・音声・ビルドスクリプト
apps/web/               React + TypeScript + Vite + PWA
tools/glyph-check/      フォント生成・実機相当環境での検証ページ
```

リポジトリは **public** で作成する。

## 検討した代替案
- **単一パッケージにまとめる**: 表記ライブラリとアプリが密結合し、多言語展開時の切り出しが難しくなるため却下。
- **private リポジトリで作る**: 別プロジェクトで private リポジトリを作った際、GitHub Actions の利用枠
  (特に macOS ランナー)を消費してしまったことがあり、それを踏まえてユーザーが public を明示したため
  却下(`gh repo create` は既定で `--public`)。

## 結果(影響)
新しい言語パッケージを追加する際は `packages/` 配下に並べる。共通コード(`kana-core` 案)の切り出しは
クメール語のネイティブ確認と表記見直しの後まで意図的に遅らせる方針にしている。パッケージマネージャーは
pnpm のみ(`npm` 禁止)を `CLAUDE.md` のルールとして固定した。

**負の影響**: public リポジトリなので、秘密情報(APIキー・音声ファイルのライセンス等)を誤ってコミット
しないよう注意が要る(`.env` は `7f9c3b6` で `.gitignore` に追加済み)。
