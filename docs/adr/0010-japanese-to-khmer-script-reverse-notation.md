# ADR-0010: クメール語話者向けに、日本語→クメール文字の逆方向表記をこの repo 内に別ディレクトリで設計する

## コンテキスト
kana-khmer は「日本人がクメール語を読む」方向(IPA → カナ)だけを扱ってきた。逆方向、つまり
クメール語話者が日本語を学ぶときの補助表記(日本語の音をクメール文字で示す)を追加したい。
**主な学習者像は、日本を旅行するクメール語話者とする**(ユーザー判断、2026-09-28)。現行アプリの
「日本人旅行者がクメール語を学ぶ」の対になる位置づけで、既存の `phrases.yaml`(シーン別の旅行フレーズ)を
再利用しやすい。就労・留学は主対象にしない(後日広げる場合は別途判断する)。

この方向は既存設計の単純な鏡像にならない。出力は発音ではなく**クメール語の正書法**(系列の選択と
慣習的綴り)なので、`khmer-kana` に無い知識が要る。音韻・正書法について、次の点が
成り立つ見込みである。いずれも文献(Huffman、Headley、Wiktionary の借用語見出し)で机上確認できる
水準で、**ネイティブ確認待ちにしない**。ただし**まだ文献で確認していない**(確認は設計書 `docs/ja-khmer-spec.md`
の作成時に行い、対応表の根拠として記録する)。

- **母音長**: クメール文字は母音の長短を必ず書き分ける。「長短を書かない」選択肢は無く、
  日本語の短い開音節(か)を長い開音節(កា)で書けば、長音との区別が潰れる(短母音の開音節は
  声門閉鎖を伴う ◌ះ/◌ៈ になる)。
- **濁音・ふ**: 外来語表記の慣習がある(g=ហ្គ、z=ហ្ស、f=ហ្វ、b/d=ប/ដ)。系列を変える
  ◌៉・◌៊ もある。「対応が無い」のではなく「慣習を採るか」の問題。慣習が無いのは つ /ts/ 等。
- **促音**: 閉音節の末子音で近似できる見込み。coeng による重ね書きは、現代語では重子音として
  読まれないので使わない。
- **拗音**: coeng+យ は候補だが、系列規則で母音が変わる(ព្យា=/pjiə/)ので頭子音ごとに確認が要る。
- **撥音**: ម ន ង の末子音で、環境差をライトでも書ける見込み。
- **ら行**: រ か ល か。プノンペン口語では頭子音 រ が弱化する。
- **う・え・お**: 「う」は ◌ុ と ◌ឹ の二択。え・お は a系だと二重母音になるので o系(または ៊)を要する。
- **アクセント**: 日本語のピッチアクセントは H/L の2段と下がり目の位置で決まる(語+助詞で効く)。
  かなはアクセントも一意な発音も表さない。

## 決定
1. **この repo 内に作る**(別 repo にしない)。**monorepo の思想に従い、ディレクトリは既存の
   `khmer-kana` 等と分ける**(ADR-0001 の延長)。ディレクトリ名・パッケージ名は仮置き
   (`kana-to-khmer` は `packages/kana-<lang>` の命名規約と方向が逆で紛らわしいため、出力がクメール文字と
   分かる名前にする)。フォント生成・`glyph-check`・`apps/web`・`packages/content` の形式を
   どう共用するか(共通パッケージ化か相互参照か)は、**共用範囲の洗い出し後に別途決める**(未決)。
   ADR-0001 が遅らせているのは表記ロジックの共通化(`kana-core`)で、フォント・検証・UI の共用は妨げない。
   洗い出しまでの既定: 既存パッケージの**公開 API のみを `workspace:*` 依存で使い、内部ファイルの参照と
   フォント生成スクリプトのコピーはしない**(試作の既成事実で共用方式が決まるのを避ける)。
2. **入力は「発音を確定した日本語」とする**。形式は、カタカナの発音表記(長音は ー、促音は ッ、
   助詞は発音どおり)+ 任意のアクセント情報。核の位置(整数、0 = 平板)は語単位で、フレーズでは表せないため、
   アクセント句の区切り+句ごとの核とする(Wiktionary は語単位なので、句への合成規則は設計書で決める)。かな綴りから発音への変換
   (は/へ/を、おう・えい)は範囲外で、データ側で人が書く。撥音の同化(ン → ម/ន/ង)は後続音から決まる
   ので、データは「ン」とだけ書き、生成器が選ぶ。無声化は、データで印を付けるか規則で出すかを設計書で決める。
   **アクセントは東京式アクセントとし、データ源は Wiktionary の日本語見出し語(アクセント型の記載)を
   参考にする**(ユーザー方針)。Wiktionary のテキストは CC BY-SA のため、取り込む場合は帰属表示と
   継承条件(share-alike)を満たす方法を、取り込む前に確認する(未確認)。
3. **表記の思想(ユーザー方針)**: クメール文字に無い音は、**IPA の発音記号を右肩に書く**。
   ピッチが変わるものは、**文字の上に線で表す**。これは既存の右肩 modifier(ADR-0005)と声調線
   (ADR-0007/0008)の思想の再利用である。
   この方針により、2階層が実質を持つ: **詳細**は通常のクメール文字+右肩 IPA(+アクセント線)、
   **ライト**は詳細から右肩 IPA の span を機能負担量で選んで捨てたもの(ADR-0002 方式・ADR-0006 の選定法。
   別の変換表を持たない。差は記号の**追加**だけで、基底文字の選択は両階層で同じ)。何を右肩に回すか
   (濁音の有声性、つ /ts/、ふ /ɸ/、長音など。慣習的綴りで足りる音は基底文字で書く)は、
   対応表で書き分けられるかと、日本語の語彙で潰したときの衝突率(ADR-0006 と同じ測り方)で決める。
   右肩に置くのは、上付き文字(既存の右肩 modifier と同じ方式、ADR-0005)に限る。結合文字の IPA 記号は
   点線円の問題があり ADR-0003 の制約を受けるため使わない。アクセント線がライトに残るかも、
   右肩 IPA と同じ衝突率の測り方で決める。
   長短は、通常の文字で書き分ける方法が見つかっていない(短母音の開音節は声門閉鎖を伴う)ため、
   右肩の長音記号が第一候補になる(設計書で検討)。
   **クメール文字は、発音(+アクセント)を正として規則でビルド時に生成する**(ADR-0012 と同じ理由:
   規則を変えるたびに全データを手で直さない)。話者依存の選択(ら行の រ/ល など)は、語ごとではなく
   生成規則の設定(方言プロファイル)とする。規則で表せない個別の語(慣習的綴りの例外など)だけ、
   データ側に上書き(override)を持たせる。
4. **表記は必ず音声と併用する**。母語の文字で外国語音を書くと母語の音で読まれ、誤った発音が固定される
   (カタカナ英語の逆)。音声なしで表記だけを出さない。
5. **UI はかなとクメール文字の併記**とする。ルビか別行かは、判読性(クメール文字は縦に高い)と
   クラスタを DOM 要素で分けられない制約(ADR-0003)を踏まえ、`glyph-check` の実機確認で決める。
   旅行者向けなので、クメール文字の依存を薄めてかなで読めるようにすること自体は主目的にしない。
   ただし看板・駅名などを読む助けとして、かなの併記は残す。
6. **アクセントは、文字の上の線で表す**(ユーザー方針。決定3)。線を載せる対象はクメール文字の行を
   第一候補とするが、かなの行・下がり目記号 ꜜ との比較は `glyph-check` の実機確認と作業量で決める。
   声調文字(Chao トーンバー、U+02E5–E9)は Unicode 上は独立した文字で、どの文字列の後にも置けるため、
   声調と同じ方式でクメール文字の上に線を出すことは、符号化の面では妨げられない。妨げになるのは
   Unicode ではなく**現行の `kana-multi` 実装の前提**(声調線が乗る「音節」を全角カナ+右肩記号で定義し、
   幅ヒントもそれ前提。ADR-0008)で、これは変えられる。
   クメール文字の行に載せる場合(A)の追加作業は次のとおり。
   - クメール文字グリフのフォント同梱と、HarfBuzz の Khmer シェイピングとの干渉確認。右肩 IPA(決定3)も
     同じ行に載るため、書記音節の後ろに右肩文字を置く並びのシェイピングも確認する。
   - 可変幅クラスタ(下付き子音を含む)の幅の扱い。幅ヒントを出すには、ビルド時にシェイピングして幅を得る
     必要があり、生成器が同梱フォントに依存する。
   - 上に積まれる母音記号との縦の衝突と、線の高さの設計。
   - 既存のクメール語フォントの GSUB/GPOS と、声調の規則の統合。
   - 声調文字とクメール文字でスクリプトが分かれる境界での振る舞い(ADR-0008 の二重符号化が効くか)。
   - 区切り文字・幅ヒントが、クメール文字の行分割・コピー・読み上げに与える影響。CSS で線を描く方式も実装案になる。
   - 輪郭は書記音節ごとにしか置けず、モーラごとには置けない。
   これは作業量の見積もりであって、不採用の理由ではない。
   表現の設計としては、Chao 5段は日本語の H/L 2段に対して過剰精度になりうる点と、声調が音節単位なのに対し
   日本語アクセントはモーラ単位の高低と下がり目の位置で決まる点を、符号化の設計時に扱う
   (高い部分に線を引く、下がり目のみ示す等)。既存の符号化をそのまま流用する前提は置かない。
   声調文字を使う案は `kana-multi.woff2` を `apps/web` に採用することが前提で、それは ADR-0014 では未決。
   ꜜ・上線はこの前提に依存しない。
7. **検証は二本立て**: (a) 生成したクメール文字を独立のクメール文字→IPA 変換で読み戻す自動テスト
   (ADR-0009 に倣い、生成関数を再利用しない)。読み戻し表は生成側の対応表を参照せず、Wiktionary の
   クメール語見出し語の発音データ(ADR-0006 で使用済み)から系列×母音記号→母音を抽出して作る。対象は
   生成器が出しうる綴りに限る閉じた表で、クメール語一般の書記→発音変換は作らない。(b) クメール語話者の音読 × 日本語話者の聞き取り。
   (a) は系列の読み変わりの取り違えをネイティブ確認前に機械的に落とす。(b) の確保は
   `docs/design.md` §8 の既存ブロッカー(クメール語話者の確保)に乗る。

対応表(基本46音・濁音・拗音・撥音)そのものは ADR に書かず、新しい設計書(未作成、仮称
`docs/ja-khmer-spec.md`)を正とする。表記の確定・ネイティブ確認は設計書側の状態として管理し、
本 ADR は、既存教材の調査と、コンテキストの音韻・正書法の文献確認が済んだ後に、
   ユーザーの明示承認をもって accepted にする(ユーザー判断、2026-09-28。学習者像は旅行者で確定済み)。共用方式は新しい ADR で決め、
本 ADR の参照に足す(accepted の条件にはしない)。

## 検討した代替案
- **別 repo で作る**: フォント・実機検証・UI・データ形式を共用できなくなるため却下(ユーザー判断)。
- **`khmer-kana` の中にそのまま足す**: 出力が正書法で、`khmer-kana` にクメール正書法の知識が無く、
  責務が曖昧になるため、ディレクトリは分ける。
- **既存教材の慣習的な表記をそのまま採る**: カンボジアの日本語教育(国際交流基金、送り出し機関の教材等)に
  既存の慣習がある可能性が高く、食い違うと学習者が混乱する。**調査してから決める**(未調査)。
  採らない場合は理由(一貫性が無い、長短を書き分けない等)を本 ADR か設計書に残す。
- **かなを最初の1〜2週で教え、クメール文字表記は最初期だけにする**: 就労者・留学生向けなら有力だが、
  旅行者(短期利用)には学習負担が大きすぎるため、主案にしない。
- **クメール文字だけで日本語を表記して学習させる**: かなを読めるようになる動線が無く、看板・書類で使えないため却下。
- **ローマ字併記のみ**: ラテン文字の読みが追加負担になるため、単独では採らない(併記は可)。
- **音声のみで教える**: 表記を不要にする理由にはならない。音声は代替ではなく必須の併用(決定4)。

## 結果(影響)
- 多言語展開(ヒンディー語・タイ語等)の系列とは別軸の「逆方向」が増える。共通化(`kana-core`)を
  検討する際、この方向の要件も入力にする。
- 未確定・未着手: ライトで何を残すか(衝突率の実測と、クメール語として自然に読める寄りか日本語音に忠実寄りかの方針)、
  既存教材の調査、Wiktionary のアクセントの取り込み方(語単位→句への合成、CC BY-SA)、設計書の作成。
- 未決: アプリを1つ(UI 言語切替)にするか、分けるか。PWA のインストール単位と i18n の設計量が変わる。
- `apps/web` はクメール語 UI(i18n)が要る。右肩 IPA とアクセント線の凡例・説明も、クメール語で用意する。ライトでもクメール文字の Web フォント(Noto Sans Khmer 等、OFL)の
  同梱と、古い Android WebView での coeng の描画確認が要る(ADR-0016)。フォントの3系統(ADR-0014)に
  4つ目を足すかの判断を伴う。
- `packages/content` の `phrases.yaml` は日本語⇔クメール語の対訳を既に持つ。新規データを作る前に、
  既存データの `ja` に発音とアクセントを足す案と比較する。旅行者にも看板・駅名は漢字で、
  本設計はかなまでを範囲とする(漢字は範囲外)。
