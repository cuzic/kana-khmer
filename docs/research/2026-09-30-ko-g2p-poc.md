# 韓国語 G2P(ハングル→丁寧な標準発音)の調査と PoC

調査日: 2026-09-30。作業場所: `~/ko-pron-dict`(この repo の外。未コミット。使い方は同ディレクトリの `README.md`)。
目的: 韓国語字幕→カナ変換(ADR-0024 の ko-kana の前段)に使う、発音ハングルへの変換の精度を上げる。
決定は [ADR-0029](../adr/0029-ko-subtitle-g2p-on-device-poc-python.md)(proposed)。ここには経緯・測定結果・未解決を残す。

## 1. 前提の整理

- 目標は**丁寧な標準発音**(標準発音法)。自然な連続発話ではない(ユーザー判断)。
- 実行は**ブラウザ拡張の端末内**を想定(字幕を外部に送らない。ユーザー判断)。Rust/WASM への移植は PoC の後。
- 数詞(K)も対象に含める(ユーザー判断)。
- Netflix の字幕は、テスト・学習データに使わない。利用規約上の扱いは公開前に確認(未確認)。

## 2. 既存ツールの調査

| ツール | 状況(2026-09-30 時点) |
|---|---|
| g2pk(Kyubyong) | 最終 push 2022-03。PR 2 件が放置。PyPI 0.9.4(2020-08)。Apache-2.0 |
| g2pkk | 2022-09。g2pk と完全に同じ結果(改善・悪化とも 0) |
| g2pk2 / g2pk3 | 2023。分かち書きを越える連音を止める。同じ点数・同じ差(g2pk3 は g2pk2 の派生とみられる) |
| g2pk-go | 2026-02。Go 実装(内容は未確認) |

g2pk は mecab-ko で形態素解析し、その品詞タグ(`/P /J /E /B` の印)を見て規則を適用する。`annotate()` が入口で、
mecab の `(表層形, 品詞)` の列だけを使う。文脈依存の入口はここだけ。

## 3. データの構築

- **Wiktionary 辞書**: kaikki.org の抽出データ(約 205MB)から 32,030 語の発音ハングルを取り出した。`sounds` の
  `other: "[문뻡]"` が発音ハングル。カテゴリから漢字語(13,798 語)・合成語の濃音化(223 語)などのフラグも取れる。
  - 発音ハングルに長母音の印 `(ː)`(9,861 件)と `/` 区切りの複数形があり、正規化した。
  - **Wiktionary の発音は `{{ko-IPA}}` の規則出力で、独立した正解ではない。** ㅐ/ㅔ、ㅒ/ㅖ、ㅙ/ㅚ/ㅞ を区別しない。
- **最小対テスト集**: 仕様 `minpairs/SPEC.md`(現象 A〜K)。Claude と Codex が独立に案を作り、相互レビューした。
  - 採用 99 組・196 item(Claude 案 + Codex 案、レビューで drop を除外)。K(数詞)は 1 回目のレビューで「仕様外」として
    drop されたため、K だけ再レビューした(ok 全件。`층` の品詞は mecab-ko-dic では NNG に修正)。
  - **ネイティブ確認前。** `confidence: low`・`variants_allowed`(許容形)を含む。
- **UD Korean**: Kaist(人手注釈、約 2.7 万文)・GSD・PUD を取得(`data/ud/`、CC BY-SA 系)。GSD の品詞は KOMA による
  自動付与で正解ではない。

## 4. 測定結果

### 4-1. 辞書 32,030 語(単語単体)での g2pk

正解率 94.9%(ㅐ=ㅔ 等を統合)。不一致の内訳: 語彙的な濃音化の取りこぼし 1,121、その他 420(多くは `의→이`・`쟈→자` 等の
正解側の表記ゆれ)、ㄴ/ㄹ挿入 49、g2pk のみ濃音 35。**単語単体では、失敗の大半は語彙的で、辞書で直せる。**

### 4-2. 最小対 188 item(文脈つき)

| | 正解 |
|---|---|
| g2pk / g2pkk | 149 (79.3%) |
| g2pk2 / g2pk3 | 151 (80.3%) |
| **PoC(`engine.py`)** | **179 (95.2%)** |

- g2pk の失敗の最大原因は、品詞ではなく**分かち書きを越えた連音・流音化**(`책을 읽고→채그 릴꼬`)だった。g2pk2/g2pk3 は
  これを止めて I・B 群を改善したが、標準発音法 제15항の「実質形態素の前の連音」(`옷 안→오단`)まで止めて G 群が
  25/26→14/26 に悪化した。PoC は、体系の直後・ㅏㅓㅗㅜㅟ の前だけ連音を戻した。
- K(数詞)は g2pk が助数詞ごとの数詞の系列を選べない(`3명→삼명`、`6월→유궐`)。助数詞の表で直った。
- **この点数は開発用データでの点数。** 失敗を見ながら規則を直したため、過学習を含む。未見データでの成績は未測定。
- 残りの失敗 9 件: mecab の品詞誤り 5 件(`감기 전에`・`안기 전에`・`함께 신자`)、辞書にない合成語の ㄴ挿入 4 件(`밤이슬`・`물약` 等)。

### 4-3. 実テキスト(UD Kaist の dev+test、4,353 文)

Kaist の正解の形態素境界から、濃音化が必要な箇所を拾い、エンジンの出力が濃音化しているかを数えた。

| 現象 | 箇所 | 取りこぼし |
|---|---|---|
| A: 用言語幹 ㄴㅁ+語尾の濃音化(제24·25항) | 33 | 0 |
| B: 連体形 -ㄹ+次の語の濃音化(제27항) | 607 | 6 (1.0%) |

- **最小対は、実テキストでの頻度を大きく過大評価している。** A 型は 4,353 文で 33 箇所しかなく、全部正解だった。
- mecab と Kaist の品詞の不一致(語節の 7.2%、粗い品詞列の不一致は 10.8%)の大半は、発音と無関係な体系の違い
  (`본래` を副詞/名詞、`한` を数詞/冠形詞、`말했으니` を動詞/名詞+하다)。
- 限界: Kaist は書き言葉(新聞・文学)。縮約語形は検出器が拾えず除外している。**口語(字幕)では A 型が多く、mecab の精度も
  下がる可能性があるが、今回のデータでは測れていない。**

## 5. 決定と見直し

- ADR-0029 の 4(Jev は実行時に使わず、オフラインの教師に限る)は、**Kaist の人手注釈(約 2.3 万文の正解の品詞・境界)で足りる
  部分がある**ため、見直しが要る。品詞由来の曖昧さは、Kaist から端末内で動く判定器を作れる。Jev の韓国語での有効性は
  未検証(API キー未取得)。
- 単語間連音の方針: 標準発音法 제15항が定める範囲に限る。体系の直後の、ㅏㅓㅗㅜㅟ で始まる実質形態素の前。依存名詞(줄・것・수)
  の後は連音しない(最小対の正解に合わせた。標準発音法の解釈としては、ネイティブ確認が要る)。

## 6. 未解決・次の一手

1. **実文の正解つきテスト集**を作る(未見データでの成績を測るため)。抽出元は韓国語基礎辞典の例文(API キーが必要。未取得)、
   Tatoeba(韓日対訳、CC BY)、Kaist。標準国語大辞典・Codex・Claude の一致で下書きを作り、ネイティブが確認する。
2. **口語のデータ**(KsponSpeech、「모두의 말뭉치」の口語部分。入手条件は要確認)で、mecab の精度と A 型の頻度を測る。
3. 辞書にない語の ㄴ挿入・濃音化(合成語・外来語・固有名詞)が実文でどれだけ誤りを生むかを測る。辞書を学習用と評価用に分ける。
4. mecab の品詞誤りを直す、端末内の判定器(Kaist を教師に)を検討する。
5. 曖昧な助数詞(`분`=分/人、`번`=回/番号 等)の文脈判定。
6. Rust の形態素解析(lindera / vibrato + ko-dic)が mecab-ko と同じ品詞を返すか、辞書のサイズ(WASM 化の前提)。
7. 最小対のネイティブ確認、PoC の `packages/` への取り込み(その際は別 ADR)。
8. 字幕の取得方式(表示された DOM を読むか、通信から字幕ファイルを取るか)。DOM 方式は文脈が現在の cue と直前の数行に限られる。
